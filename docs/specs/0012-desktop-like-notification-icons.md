# Spec 0012：通知图标与角标向手机桌面对齐、详情文字居中

状态：已返修并覆盖安装，等待用户复验（2026-09-28），PR #127 保持草稿。产品取舍 Q1=B、Q2=A；下列返修要求覆盖首版中排除 Agent Mirror、允许充电时大幅缩小图标的实施选择。见[返修记录](../poc-logs/20260928-spec0012-recheck/README.md)。

返修基准：用户明确以桌面截图右下方 ChatGPT、飞书、RearCue 的独立大图标为尺寸参考，飞书角标为右上落点参考；应用通知与 Codex／Claude 任务内容两种详情均需居中。此前[验收记录](../poc-logs/20260928-spec0012-notification-visuals/README.md)保留为被否决版本的历史证据，不能作为最终验收通过结论。

跟踪：[Issue #124](https://github.com/Anthony8017/RearCue/issues/124)，标签 ready-for-agent。

## Problem Statement

机主在背屏 Dashboard 上看到的通知图标及数字角标太小，与手机主屏桌面图标相比不够清晰；点开 Detail View 后，上下留白过大，文字没有按期望居中，有限的阅读空间未得到充分利用。

原 Icon Set 网格的图标虽标称 96dp，但三列网格最终整体缩放进背屏安全区域，角标底片和数字也一起缩小。因此仅增大标称尺寸不能保证实机效果改善。详情原先上下各 24dp，按仓库记录的本机 450dpi 推算约为 68px；这些是规格编写阶段核对的基线，实施阶段的重新采样见验收记录。

## Solution

- **图标与角标向手机当前主屏桌面对齐**：以本机实际桌面的图标、圆角轮廓、角标样式和比例作为视觉参照，调整背屏最终显示效果，使应用和数字更容易辨认。优先保留每行三个、最多两行六个图标；空间不足时允许适当缩小，不通过减少容量换取大图标。超过六个应用仍用「+N」提示。
- **详情优先居中**：标题与正文整体在避开 Camera Band 和屏幕圆角后的可读区域内上下居中，标题及正文的每一行都水平居中。短内容不强行贴顶；长内容超过一屏时从开头显示，并保留滚动阅读能力。
- **上下最小留边各 8px**：采用屏幕物理像素口径。短内容因居中产生的实际空白可以更大；长内容尽量利用可读高度。既有右侧 8px 是可用阅读范围的边界，不要求每行文字墨迹贴右边，也不改成右对齐。

## User Stories

1. 作为机主，我希望背屏通知图标更容易辨认，以便不翻转手机也能看清通知来自哪个应用。
2. 作为机主，我希望图标大小和样式尽量接近手机当前桌面，以便两处呈现有熟悉、一致的观感。
3. 作为机主，我希望数字角标随图标同步改善可读性，以便一眼看清该应用有多少条活动通知。
4. 作为机主，我希望角标的位置、轮廓和图标之间的比例接近桌面，以便避免角标显得过小或突兀。
5. 作为机主，我希望大小取舍优先保留一屏六个应用，以便同时看到更多通知来源。
6. 作为机主，我希望网格保持每行三个、最多两行，以便沿用熟悉的排布。
7. 作为机主，我希望不足一行的图标仍居中，以便两个、四个或五个应用时界面不偏向一侧。
8. 作为机主，我希望第七个应用起继续显示正确的「+N」，以便知道还有多少应用未显示在网格内。
9. 作为机主，我希望同一网格档的图标大小不随通知数量变化而忽大忽小，以便通知增减时画面稳定。
10. 作为机主，我希望单条与多条通知场景都清晰可读，以便切换场景后不会出现难以识别的图标或数字。
11. 作为机主，我希望一位和多位角标数字都完整可读，以便计数增大时不被裁切，也不与相邻图标重叠。
12. 作为机主，我希望角标仍表示各应用的 Active Notification 条数，以便视觉调整不改变数字含义。
13. 作为机主，我希望最新通知对应的应用仍优先排列，以便继续快速找到最近的通知。
14. 作为机主，我希望点开短通知时标题和正文作为整体上下居中，以便阅读中心落在背屏可见区域中央。
15. 作为机主，我希望标题及正文的每一行都左右居中，以便换行后仍保持我选择的居中样式。
16. 作为机主，我希望居中以避开相机带的可读区域为准，以便文字不会为了对齐物理屏幕中心而被挡住。
17. 作为机主，我希望详情上下最小留边各为 8px，以便内容较多时充分利用屏幕高度。
18. 作为机主，我希望短内容居中时允许上下空白超过 8px，以便居中优先于机械贴边。
19. 作为机主，我希望圆角附近的文字仍完整可读，以便缩小边距后不会缺字。
20. 作为机主，我希望圆角避让不会把整篇正文的右边距大幅加宽，以便扩大高度时不牺牲整篇的阅读宽度。
21. 作为机主，我希望超长正文从开头显示并能滚到末尾，以便上下居中不会把首尾内容挤出屏幕。
22. 作为机主，我希望长文滚动时每一行仍保持水平居中，以便同一详情的排版保持一致。
23. 作为机主，我希望应用名重复标题仍按既有规则省略，以便详情直接呈现有用内容。
24. 作为机主，我希望只有标题或标题被省略的通知也正确居中，以便不同通知格式都能正常阅读。
25. 作为机主，我希望点开、收起、通知消除及详情展开动效保持既有行为，以便视觉改进不改变使用习惯。
26. 作为机主，我希望充电和通知高亮时图标、角标依旧清晰且不遮挡电量数字，以便不同背景下都能看清通知。
27. 作为维护者，我希望验收比较最终背屏效果和桌面参照，以便不会把只改标称尺寸当成已经解决问题。
28. 作为维护者，我希望几何检查覆盖居中、边界和容量，以便后续改动不会重新引入裁切或排布偏移。
29. 作为机主，我希望 Codex／Claude 任务内容与应用通知正文同样逐行居中、短内容整体上下居中、上下最小 8px，以便两种详情都符合阅读预期。
30. 作为机主，我希望充电时图标也尽量保持桌面独立大图标的大小，避免插电后为电量数字又显著缩小。
31. 作为机主，我希望角标像桌面飞书一样伸出图标右上角，而不是整枚压在图标内部。
32. 作为机主，我希望六图标、溢出提示和电量能同时看清；充电时允许 +N 在网格下方、电量左侧剩余空白区居中。

## Implementation Decisions

- **改动边界**：本功能落在 :rear 的 Icon Set 呈现、Detail View 布局及其设计令牌和几何计算中。:core 的通知选择、计数和状态流转继续作为数据来源；不改变通知采集、投送、权限、存储或外部协议。
- **桌面参照采样**：以用户指定的右下独立大图标为准，实测 186px，按两屏物理 dpi 换算背屏目标约 162px；角标 65px，换算约 56.5px；右上外探 18px，换算约 16px。充电/非充电、单条/多条均核对最终尺寸与位置。截图像素不能直接跨屏比较，也不能只验证颜色就宣称样式相近。
- **容量约束**：保留三列两行、最多六个应用及「+N」规则。图标尺寸和间距须结合最终缩放共同调整；六个应用的容量优先于与桌面尺寸完全相同。网格内不同数量仍保持稳定尺寸和每行居中。
- **角标呈现**：调整底片、字号和位置时独立核对最终可读大小，不能继续任由整组缩放把数字压回过小状态。保留完整活动通知计数，不在本功能中新增计数封顶、应用内部未读数或替代符号的语义。
- **通知语义**：每个应用一枚图标、时间倒序、单条与多条通知的切换判据、点开最新一条 Detail View 的行为均沿用既有契约；不将通知条数与应用个数混用。
- **详情布局**：标题和正文共同参与垂直布局；高度足够时整体上下居中，两者均逐行水平居中。省略标题后用实际剩余内容重新居中。正文超出可用高度时沿用滚动阅读，从开头进入，首尾均可达。
- **阅读边距**：上下各 8px 是最小内容边距，不能直接替换成 8dp。可读区域仍避开相机带和屏幕圆角；横向居中基于该可读区域，既有右侧 8px 用作阅读范围边界。
- **圆角处理**：利用实际文字落位及其可用范围处理局部圆角避让。不能把整篇文字的顶底范围简单扩展到屏缘后，统一扩大整篇右边距。优先复用既有 DisplaySafeArea / SafeArea 几何出口；如须扩展输入或输出，保持现有调用方的行为兼容。
- **共享阅读规则**：按用户返修确认，Agent Mirror 也采用上下最小 8px、逐行水平居中、短内容整体垂直居中；会话标识与实际正文共同参与布局。通知长文从开头进入；Agent Mirror 保留新输出跟随滚底、上滑暂停和恢复跟随行为，两者只共享版式几何，不混用滚动策略。
- **充电容量**：按实际相机带与圆角利用空间，不为旧保守矩形、空行或未显示的 +N 留位而把图标压小。必要时在圆角安全范围内调整电量纵向落点，保持电量字号与光效；充电下 +N 在网格下方、电量左侧可用空间居中。
- **既有视觉与交互**：保留纯黑全屏卡底、相机带上的纯视觉背景、高亮和充电光晕、点击区域、详情展开收起动效以及图标对电量数字的避让。图标变大不等于可以越过内容安全边界。
- **实施策略**：以可逆的视觉调整完成，不新增设置项、模块或持久化字段。现有投送、保活与许可 ADR 不受影响，无需新增 ADR。

## Testing Decisions

- **测试原则**：只验证用户可见结果与输入输出不变量，不断言 Compose 节点嵌套、内部调用次数或某个恰好等于当前实现的常量。对纯配色、字号和对齐修饰不编写镜像实现的单元测试。
- **主要验证边界**：以 :rear 接收通知呈现数据和显示几何后产生的最终可见布局为主边界。复用 IconGridTest 与 DisplaySafeAreaTest 所覆盖的既有布局、几何能力；仅在新增或改变几何决策时补充必要用例，不为本功能另建平行布局系统。
- **图标布局不变量**：覆盖 1/2/3/4/5/6/7+ 个应用、同一应用多条通知、通知增减切换；确认三列两行容量、每行居中、时间顺序、「+N」计数、网格尺寸稳定、角标不越界，以及有电量数字时不相互遮挡。
- **详情几何不变量**：覆盖短句、多行、只有标题、被省略标题和超长正文。高度足够时整体上下居中、每行水平居中；高度不足时首尾可滚动到达。检查上下最小 8px、相机带和圆角避让，以及局部避让不会把整篇可读宽度无故缩小。
- **既有语义回归**：沿用 DetailDisplayTitleTest 的标题显示规则，保留 Agent Mirror 的滚动跟随/暂停和恢复语义。通知计数、打开即消除所示通知、自发消除不立即收起详情等行为按当前契约检查，不重写状态机。
- **真机视觉验收**：参照 spec 0009、spec 0011 的截图与实拍流程，保存桌面参照和改动前后背屏效果；检查一位及多位角标、不同应用数量、短通知、多行通知、长文首尾、充电和高亮背景。相机带遮挡须结合布局坐标和肉眼或实拍，截图本身不能证明没有物理遮挡。
- **验收事实分层**：编译、几何测试、截图判读和真机观感分别记录。仅编译或测试通过不能宣称与桌面一致；若尚无设备取样或真机验证，明确记录未验证项，不能把推算数字当本轮实测。
- **规格编写阶段**：只整理和发布文档；上述验证在用户随后授权实施后执行，结果见验收记录。

## Out of Scope

- 为放大图标而减少为两列、降低最多六个应用的容量，或新增图标分页。
- 在本功能中把角标改成应用内部未读数、引入通知列表或改变通知消除语义。
- 新增图标尺寸、角标样式或文字对齐的用户设置。
- 全面复刻 Launcher、持续同步桌面主题，或引入新的图标包管理能力。
- 修改充电动画、电量数字样式、通知高亮规则、投送链路、Posture Gate、保活或权限策略。
- 改变详情字体家族、通知文本内容、应用名省略规则或加入更多通知元信息。

## Further Notes

- 产品取舍来自 2026-09-28 的 grill-with-docs 会话：Q1 选择 B，优先同屏六个图标；Q2 选择 A，详情每行文字居中。上下 8px 与「优先居中」合并为最小边距要求，短内容允许留下更大的对称空白。
- 本规格及用户返修确认取代通知详情与 Agent Mirror 原有纵向留白和对齐约束；相机带与圆角避让、右侧 8px 可读边界仍有效。
- [Issue #101](https://github.com/Anthony8017/RearCue/issues/101) 的三列两行容量、排序和角标计数语义继续有效。96dp 等现有标称值属于调整起点，最终以容量约束下的屏上效果验收。
- 首版虽通过 325 项自动化回归，但未覆盖角标外探、充电最终尺寸及 Agent Mirror 的新排版。用户验收失败后实测：非充电图标约 156px、充电约 114px，角标相对桌面偏左下约 16px；Agent Mirror 仍上下 32dp、左对齐。此记录用于修正验收口径，不作为达标结论。
- 规格已完成产品讨论，不以新增产品问答为开工前提；具体视觉参数由实施者根据桌面取样和上述约束确定并记录。
