# Spec 0019：托盘与桥互盯生命周期——图标 ⇔ 桥

状态：已实现收口（2026-09-30，PR #192；实机验收 4+1 场景全 PASS，归档 docs/poc-logs/20260930-1545-spec0019-tray-bridge/；取舍记 ADR 0011）。
术语采用 CONTEXT.md 的 PC 桥、托盘图标、桥地址、Bridge Link、Agent Mirror；落地时补「托盘」词条、消歧两种「看门狗」（见 Further Notes）。
测试落位经机主确认：PC 侧进程级隔离实测 harness ＋ 手机侧 Bridge Link 状态机判例，两个既有缝、零新增缝。
取舍记 ADR 0011（先补图标后关桥＝保手机优先；不合并托盘与桥）。

## Problem Statement

托盘图标是 PC 桥唯一的人机界面，机主靠它判断桥在不在。现状只保证「桥停→图标消失」，反向没有机制：2026-09-30 实测托盘自行退出后，桥**无图标跑了约 53 分钟**——机主看到「没图标」以为桥停了，实际后台还在跑、还在占端口。反过来（桥死了图标留着旧地址）历史上也发生过。机主无法信任图标，也无法知道桥的真实状态。

## Solution

「图标在 ⇔ 桥在」双向成立。托盘消失→桥自动补拉图标（3 次×10 秒）；补不回→桥自己关掉；开机自启任务自动重来（3 次×30 秒）；仍不行→彻底停，手机 Bridge Link 显示「未配置或已停用」，不再无限「连接中」。恢复＝重新登录（登录自启）或电脑上手动跑一条命令。桥被杀时留痕，可实锤来源。

## User Stories

1. 作为机主（电脑前），我想托盘图标永远代表桥的真实状态，so that 看一眼图标就知道桥在不在。
2. 作为机主（电脑前），我想托盘进程意外消失后图标 10 秒内自动回来，so that 不用手动救。
3. 作为机主（电脑前），我想托盘反复补不回来时桥自己关掉，so that 不留下看不到的后台进程。
4. 作为机主（电脑前），我想桥关掉后自动重来几次（3 次、每 30 秒），so that 短暂故障不用我管。
5. 作为机主（电脑前），我想几次都失败后系统彻底停下而不是无限重启，so that 电脑不被反复折腾。
6. 作为机主（电脑前），我想桥被杀后图标 3 秒内消失，so that 图标不会用旧地址骗我。
7. 作为机主（电脑前），我想右键「退出桥」仍是彻底退出（图标一起走），so that 手动停就是真的停。
8. 作为机主（手机端），我想桥彻底停后手机显示「未配置或已停用」而不是一直「连接中」，so that 我知道该去电脑开而不是干等。
9. 作为机主（手机端），我想网络抖动被误判「已停用」后连接恢复时自动翻回「已连接」，so that 不用手动修。
10. 作为机主（手机端），我想桥主动关自己时手机尽快显示已停用（临终通知），so that 状态变化不用等超时。
11. 作为机主（手机端），我想桥重新起来后手机自动收到新桥地址并连上，so that 不用重新手填。
12. 作为机主（电脑前），我想开机登录后图标自动出现、手机自动连上，so that 重启电脑不用记着手动开。
13. 作为机主（电脑前），我想彻底停后重新登录或跑一条命令就能恢复，so that 恢复路径明确。
14. 作为机主（手机端），我想背屏链路状态点与主屏状态行读同一份 Bridge Link 事实，so that 三处显示不打架。
15. 作为机主（电脑前），我想托盘图标保持两态配色（就绪薄荷绿／未就绪琥珀黄），so that 一眼分辨隧道状态。
16. 作为机主（电脑前），我想托盘始终只有一份，so that 不被重复图标困扰。
17. 作为机主（手机端），我想桥关掉/彻底停期间 Agent 页保持最后一帧（断线保留既有语义），so that 内容不闪没。
18. 作为机主（电脑前），我想无人值守整夜里「图标在 ⇔ 桥在」也成立，so that 长时间挂着也能信。
19. 作为开发者／排查者，我想桥与托盘退出时留下原因、信号与父进程链留痕，so that 能实锤是谁弄死的。
20. 作为开发者／排查者，我想托盘自退与补拉都有日志锚，so that 误判可复盘。
21. 作为开发者／排查者，我想进程级实测覆盖杀托盘／补拉失败／彻底停／杀桥四条路径，so that 不变量由测试守着。
22. 作为开发者／排查者，我想手机侧状态机判例覆盖超时降级与临终通知，so that 显示语义不回退。

## Implementation Decisions

- **不合并托盘与桥**（否决单进程）：桥保持零 npm 依赖，托盘保持独立 PowerShell+WinForms 进程；两者互盯（托盘盯桥已有，桥盯托盘为新增）。
- **桥新增托盘监护职责**：托盘进程退出即补拉（3 次、间隔 10 秒）；全部失败则桥优雅自关，进入重来。
- **重来引擎＝开机自启计划任务**：注册参数对齐产品节奏（失败重启 3 次、间隔 30 秒）；耗尽即彻底停，直到重新登录或手动拉起。
- **托盘自退判据保持**（父进程消失 或 连续 3 拍探不通桥端口）＋单例「接管即清场」保持；托盘退出原因留痕（区分桥没了／探不通／被接管／手动退出）。
- **临终通知**：桥主动自关前尽力通知手机（复用既有 adb 广播通道的「清除桥地址／停用」语义）；发不出不重试，靠手机超时兜底。
- **手机侧 Bridge Link 状态机**：四态语义不变，新增两条边沿——重连失败累计约 2–3 分钟降级 DISABLED（超时判停）；收到临终通知立即 DISABLED。连接恢复回 CONNECTED（既有）。
- **被杀留痕**：收到终止信号时记录信号类型、父进程链、PID、时间；桥与托盘两侧同做。
- **不改**：右键「退出桥」＝停任务＋收整棵进程树；桥地址自动 adb 推送与手填兜底；两态配色；图标资产生成；Bridge Link 三处显示同一份事实。
- **文档**：ADR 0011 记取舍（先补图标后关桥＝保手机优先；不合并的理由）；CONTEXT.md 补「托盘」词条、消歧两种「看门狗」（隧道轻看门狗／计划任务看门狗）。

## Testing Decisions

- 好测试只测外部行为（进程在不在、图标与状态在不在、健康口通不通、手机状态上报序列），不断言内部实现。
- **PC 侧**：进程级隔离实例 harness（既有托盘/隧道看门狗实测：假隧道＋独立端口＋独立临时目录）。新增断言：杀托盘→图标 10 秒内回来且桥不断；注入补拉失败→桥自关；重来耗尽→彻底停且无人再拉起；杀桥→3 秒内图标消失（既有断言保持）。
- **手机侧**：agent 模块 Bridge Link 状态上报序列判例＋背屏链路状态点映射判例（均既有）。新增：超时降级、临终通知即时降级、恢复回已连接、同值不重复上报。
- **Prior art**：既有 harness 四断言、node --test 套件、手机侧状态序列与映射判例。
- 不写 JVM 测试的部分（图标动效、气泡外观）沿仓内惯例走实机目视验收；`gradlew test` 既有基线 0 失败不回退。

## Out of Scope

- 合并托盘与桥为单进程（已否决：断屏风险＋破坏零依赖）。
- 手机端远程拉起电脑桥（等真成痛点再开票）。
- 「谁在杀桥」的来源排查（本 spec 只做留痕，排查另票）。
- 固定隧道地址／自备域名（既有决定：维持免费试用隧道）。
- 手机侧新增「电脑已停」专用状态（归入既有「未配置或已停用」）。
- 运维动作：清理失效看门狗任务、拉起当前桥（不属于本 spec）。

## Further Notes

- 直接起因：2026-09-30 托盘 12:26:45 自退（code=0）后桥无图标跑约 53 分钟；同日桥被外部信号终止 3 次。
- 取舍：误判时断屏 vs 假图标→保手机（先补后关）；不合并→保零依赖与故障隔离。三要件齐备，记 ADR 0011。
- 图标是否被 Windows 收进溢出区程序控制不了；验收口径以托盘进程在不在为准，首次出现弹气泡提示。
