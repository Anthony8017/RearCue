# Spec 0030：PC 桥镜像名单管理

日期：2026-10-05
状态：Q1–Q10 与整套设计均已确认；代码已实现并通过隔离验证，正在准备部署。

## 目标

机主从桌面 PC 桥托盘打开会话管理窗口，管理哪些已有对话进入手机镜像名单。注册指加入镜像名单，不是创建来源软件中的对话。

## 已确认

- Q1：只管理镜像名单；不通过本功能新建、改名或删除来源软件中的原对话。
- Q2：托盘打开独立会话管理窗口；关闭窗口后 PC 桥继续常驻运行。
- Q3：现有和新对话默认自动加入镜像名单，机主可手动移出。
- Q4：移出后持续停用该对话的手机镜像、等待插队、提醒、播报与对话操作入口，直到机主手动恢复；对话继续回复或进入等待均不能使它自行恢复。
- Q5：管理窗口可查找较早但尚未归档的对话，并将其加入名单。
- Q6：Q3 的「现有对话」限定当前已在手机列表中的对话；之后新建的对话自动加入，更早的历史候选只列在管理窗口，机主勾选后才加入手机名单。
- Q7：加入旧对话后，可载入本机仍保存的完整问答；载入时显示进度。来源未保存、已清理或损坏的内容不能凭空恢复。
- Q8：加入或恢复只恢复当前状态，不补发已结束的旧任务提醒和旧播报；来源当前确认仍需机主处理的待办立即提醒。
- Q9：窗口支持搜索、按来源筛选，以及批量加入、移出与恢复。
- Q10：先勾选，再点「应用」统一生效；勾选本身不立即改变手机名单。

新旧对话的默认加入仍遵循既有来源可镜像范围，不使已归档、已删除或内部子 agent 对话重新出现。

「直到手动恢复」涵盖电脑或桥重启，以及来源软件的改名、继续活动、归档后再取消归档；这些动作都不能冲掉机主的移出选择。手机断线时沿用最后已知事实，恢复连接后对齐名单。

移出与来源归档分别记录，镜像管理不替来源软件改变归档或删除状态；来源归档、删除仍优先于镜像加入。边界取舍记 [ADR 0024](../adr/0024-pc-mirror-roster-source-boundary.md)。

## 名单与旧问答

- 当前手机名册在功能首次启用时保留；较早历史候选的发现、搜索或列表刷新不会自行加入手机。新建取来源的创建事实，不把首次扫描到旧文件当作新建。
- 明确移出的选择持续保留；加入旧候选与恢复已移出的对话只改变镜像资格，不执行来源归档、取消归档、删除或新建。
- 加入或恢复时提供当前状态及当前会话的历史读取能力，沿用手机的会话选择和完整历史回看；不会因加入一个普通旧对话强行切走机主正在看的页面。
- 历史只读本机保存的记录，不启动模型、不发送 prompt、不消耗 token。历史读取与实时事件分开，历史问答不作为新完成事件进入提醒或播报。
- 当前待办必须以来源当前确认的状态为准，不把旧历史中的等待文字当作仍待处理。重复刷新或恢复不重复补发同一待办。
- 历史缺失、读取失败或来源暂时不可用时，界面明确说明，保留可用的当前内容并允许重试；不把空历史宣称为完整，也不为取历史向原对话发送消息。

## 实现所需的统一行为

- PC 桥统一保存四来源镜像资格，键使用来源及原会话身份；标题变化不改变加入或移出选择。
- 名册、实时事件、旧问答和手机对话操作均遵循同一镜像资格；已移出的旧消息或迟到消息不能重新带回该对话。
- 在线正常使用下，应用移出后 2 秒内手机名单与相关入口对齐；已锁定的移出会话清锁回自动，移除其正在或待播内容，其他会话沿用既有显示与播报规则。断线期间保留最后已知事实，连接恢复后立即对账。
- 管理写入口只供电脑本机窗口使用，与公网隧道分开；手机仍使用既有会话选择与对话操作，不新增手机名单管理入口。
- 名单保存失败时保留此前生效的选择并明确报错；不能静默清空移出记录或假报成功。

## 会话管理窗口

- 从托盘「管理会话」入口打开；已有窗口时再次点击激活同一窗口，避免重复窗口造成不同名单。
- 列表显示可读会话标题、来源、目录与镜像资格（已加入、已移出、可加入）；名称沿用来源软件，不展示完整 sessionId。
- 文本搜索覆盖标题和目录，来源筛选保留「全部」；加入、移出与恢复可对明确勾选的会话批量操作，选中数量持续可见，搜索或筛选不隐式扩大操作范围。
- 来源不可用或归档事实无法确认时明确说明；临时失联不视作删除，不默默清掉已保存的名单选择。
- 加入、移出与恢复先成为窗口内草稿，点「应用」后统一保存并生效，成功与失败均明确反馈；未应用就关闭只放弃窗口草稿，已应用的名单选择继续生效，PC 桥继续运行。
- 窗口打开期间来源归档、删除或可用性变化，应用时仍以当前事实为准；失效候选明确提示刷新，不能让旧勾选使已归档或已删除会话重新出现。

## 沿用的产品边界

- 四来源共用 PC 桥：ZCode、Codex、Claude Desktop 的 Code/Cowork、DeepSeek Harness。Claude Chat 仍不镜像。
- 来源软件的归档事实继续决定对话是否可见；取消归档由来源软件发起。本功能的加入、移出与恢复只管理镜像资格。
- 会话标题继续跟随来源软件；手机 Session Picker 与 Session Lock 仍负责选择显示哪个在册会话。
- 已合入主线 #318/#319：Codex 当前提供方/置顶与 Claude 当前账号/组织的桌面可见范围同样限制候选与加入，镜像资格不能绕过来源准入。
- 管理窗口按需打开；托盘、桥地址、隧道自愈、开机自启和退出桥的既有规则继续适用。

## 已核对的现状

设计基线为 `origin/main` 的 `fa471802279e623f2661a5748924c044cab74b6e`，并与 GitHub main 的 SHA 核对一致。

- 桥已有统一会话名册、实时离册事件、来源归档事实和防止旧事件重新入册的规则；尚无机主维护的镜像名单或会话管理窗口。
- 身份缓存保存标题和工作区，用于名称恢复，不是镜像注册表。
- 手机已实时处理名册变更，可复用现有对账与清锁出口；机主移出与来源归档需要保留各自的含义。

旧问答读取尚不是四来源统一的现成能力：ZCode 已有本地完整问答读取；Codex、Claude 保存的会话文件可用于补建问答，但当前历史接口仍主要依赖桥内存；DSH 的已有回放限制为 40 条、单条 8000 字，需接入完整原始日志读取。Q7 已确认的是待实现产品目标，不是现状保证。

DSH 官方已安装代码与文档已核实：默认历史路径为 `~/.dsh/sessions/<projectKey>/<encoded-id>/session.v4.jsonl[.zstd]`，根目录可配置；文件保存会话 header 与原始事件，压缩形态为 Zstandard 拼接帧。官方 `sessionQuery.readSession(id)` 提供不激活旧会话的完整、经校验原始日志；DSH 宿主关闭时需要本地只读解码。现有 `deriveMessages()` 是可被上下文压缩替换的投影，不能当作完整原始问答。

核对证据来自已安装 `DeepSeek Harness/resources/app.asar` 内的 `@deepseek-ai/dsh-session-persistence-jsonl`（路径与只读打开契约）、`dsh-session-query`（原始日志读取契约）、`dsh-session`（V4 与事件 schema），未读取私人会话正文、启动模型或调用写接口。新历史读取继续沿用已有主会话、机主提问与注入内容的过滤规则。

## 验收重点

1. 四来源主会话可搜索、加入、移出和恢复；历史候选不会因扫描自行上手机，新建对话按规则自动加入。
2. 移出后列表、正文、等待插队、提醒、播报及对话操作入口一致停用；新活动、改名、重启、归档再取消归档和迟到事件均不能复活已移出的对话。
3. 原对话不因镜像管理而新建、改名、归档、删除或停止运行；来源归档、删除仍使镜像隐藏。
4. 加入或恢复的历史只取本机已保存记录，不调模型、不消耗 token；真实当前待办可提醒，历史完成、失败与已解决等待不补提醒或播报。
5. 搜索、来源筛选与批量勾选范围准确；未点「应用」不改变手机名单，成功后统一生效，失败不丢此前选择；关闭窗口桥继续运行，断线恢复对齐。

## 实施边界
