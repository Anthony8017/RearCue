# Spec 0028：背屏默认进入会话列表

日期：2026-10-05
状态：grill-with-docs 已收口，Q1–Q6 均按推荐确认；已实现，本地回归与 APK 构建通过，未装机，实机验收待完成。

## 目标

RearCue 接管背屏时尽量先显示 Agent 会话列表，让机主先选择要看的会话。
本文的「列表页」统一指 CONTEXT.md 的 Session Picker，不指通知页，也不新增通知与会话混合列表。

## 已确认

- Q1：沿用现有 Agent 会话列表作为本次讨论的默认入口。
- Q2：首次接管、系统抢回后重新投送、断线恢复，都先显示会话列表；通知同时存在、只有一个会话、已锁定某个会话均不改变此默认入口。
- Q3：Waiting-for-Approval、首次出现的 Pending User Question、Voice Broadcast Follow 保留直达对应内容的例外。
- Q4：Dashboard 已接管但暂无 Agent 会话时，显示「暂无会话」的空列表，并保留通知页入口。
- Q5：待确认、待答问题处理完，或整组语音播完后，恢复插队前的 RearCue 页面；原先是列表则恢复列表，原先是通知页或会话正文则恢复对应页面。插队期间机主手动切页，保留机主最新选择。
- Q6：插队前 Dashboard 不在背屏、没有原 RearCue 页面可恢复时，结束后显示默认会话列表；没有任何显示理由时照旧退屏，不为留下列表延长投送。

语音队列逐条展示来源会话，只在整组结束后恢复，避免每条之间闪回列表；暂停不算结束。此项明确取代 ADR 0023 的「播完留在最后一条回复」。

本次调整默认显示入口；既有自动投送条件、手动退出与退屏条件继续适用，空列表不新增自动投送理由。

## 默认入口与返回

| 场景 | 显示规则 |
| --- | --- |
| 普通首次投送、手动重投、系统抢回后的重新投送 | 先显示会话列表 |
| 链路断→通，Dashboard 已在屏或既有规则触发重新投送 | 先显示会话列表；不额外扩大投送条件 |
| 通知并存、只有一个会话、已锁定会话 | 仍先列表，不自动打开通知或锁定会话正文 |
| 已投送，但无在册会话 | 空列表显示「暂无会话」，保留「自动」行及其通知页入口 |
| 手动从通知页进入 Agent 页 | 先显示列表；无会话也显示空列表 |
| 待确认、新待答问题、正在播报 | 直接显示对应内容，暂时收起列表 |
| 插队期间系统重投或链路恢复 | 有效插队继续显示，不改写最初的恢复目标 |
| 所有插队结束，原页面仍有效 | 恢复原页面及列表开关；恢复有效的会话或通知详情阅读状态 |
| 原页面不存在或恢复目标会话已失效 | 默认列表；没有会话则显示空列表，不能恢复已归档会话 |
| 插队期间机主手动选页或会话 | 保留最新选择，不恢复旧页面；同组后续播报不重新覆盖该选择 |
| 机主明确退出或全部显示理由消失 | 依既有规则退屏，不自动为返回列表重新投送 |

## 沿用的交互边界

- 默认列表只决定进入时的落点，不新增定时返回列表；连续显示期间尊重机主手动选页，普通新通知、会话和输出不抢页，列表实时刷新。
- 点会话条目仍选择该会话并关闭列表；点列表外仍不改会话锁，关闭后显示当前会话；点「自动」行仍进入自动档，右侧通知入口仍不改锁直接进入通知页。
- 手动从通知页进入 Agent 页时仍先显示列表；没有在册会话时采用本 spec 的空列表。手动选择、列表排序、六条完整行与字号均沿用现有规则。
- 打开列表、点列表条目、插队自动显示正文均不标已阅；机主点按正文才标已阅。
- Waiting-for-Approval 维持最高视觉优先级；仍有插队需要显示时，先显示该内容，结束返回不得覆盖尚未处理的插队。
- 重叠插队继续按待确认 → 新待答问题 → 播报的视觉优先级显示；高优先级结束先回仍有效的插队，全部结束才恢复最初被打断的页面或机主最新选择。
- 待答问题未答可手动切走，同一问题不反复抢屏；真正待批准的不可切走规则继续适用。
- 语音暂停或来电临时中断不算整组结束；继续播报仍属同组。跳过或失败一条时，有后续就继续，整组耗尽才返回；清空队列或关闭播报也结束本组并按返回规则处理。
- 插队来源会话消失或归档后，不继续展示失效内容；还有有效插队则继续，否则返回。既有在册对账与清锁规则不变。
- 机主明确退出时，不因插队结束自动重新投送；系统抢回后的重投及播报回屏继续走既有触发条件。

## 验收要求

1. 首次投送、手动重投、系统抢回后重投、在屏断线恢复均先显示列表；覆盖通知并存、单会话、锁定会话及无会话四种情况。
2. 列表直接出现，不先闪过通知页或 Agent 正文；空列表可直接进入通知页，新会话到达只刷新列表。
3. 三类插队显示正确内容；待确认优先，同一待答问题不重复抢屏。
4. 从列表、通知页、通知详情、会话正文分别被打断，全部处理完能恢复有效的原页面；从列表开始必须恢复列表，不能只回 Agent 正文。
5. 多条语音逐条切换来源会话，条目间不返回列表；整组结束、清空或关闭才返回，暂停与来电不返回。
6. 插队重叠、系统重复重投和链路恢复均不丢失最初恢复目标；插队仍有效时不提前返回列表。
7. 机主在可切走的插队期间选页或选会话，后续输出、同组后续播报及插队结束均不覆盖其选择；明确退出后不自动回屏。
8. 插队前没有 Dashboard 或原会话已归档时，按默认列表及既有退屏条件收口；已归档会话不重新出现。
9. 列表操作与自动正文显示不标已阅；点正文才标已阅。会话锁、通知操作、排序、六条行高与字号、充电背景及投送门控无回归。

实施验证沿用现有事件序列判例与背屏实机验收，不以内部字段替代可见行为。播报接线已改用队列的整组存续事实，单条跟随目标清空不再代表整组结束。

## 实现与本地验证（2026-10-05）

- DashboardCore 的三类插队改为覆盖显示投影，底下的页面与列表开关保持；普通首投、重投及链路恢复默认打开列表，整组结束释放播报持有权。
- 临时插队恢复原正文会话，不改持久会话锁；阅读滚动、回看快照及列表滚动在页面层按阅读上下文保留，手动选会话仍回实时跟随。
- 空列表显示「暂无会话」，保留「自动」及右侧通知入口；同组后续条目同时尊重手动选页与视觉跟随暂停。
- 默认入口判例包含三类重叠、重投、归档、手动覆盖、首次播报早于投送就绪、通道中断恢复等事件序列；真实播报队列验证条目间不结束、队列耗尽或清空才结束。
- 本地测试：core 269、app 152、rear 260、agent 152、notification 23，共 856 项，全部通过，无跳过；调试 APK 构建成功。

## 覆盖的旧约定

- [Spec 0013](0013-content-pages.md)：取代「两页都有内容默认通知页、只有一边有内容显示该页」的默认入口；链路恢复改为列表入口，原有连续显示期间不抢页的规则保留。
- [Spec 0016](0016-session-picker.md)：取代「仅手动进入 Agent 页且有会话才默认开列表、无会话默认正文空态」的入口边界；选中会话关闭列表等操作保留。
- [Spec 0027：待答问题](0027-codex-pending-user-question.md)：新问题打开对应内容，答完恢复原页面及列表；机主手动选择优先。
- [ADR 0023](../adr/0023-voice-broadcast-follow-and-reclaim.md)：取代「播放结束停在最后一条回复」，改为整组结束恢复原页面或默认列表；播报跟随、回屏与用户控制继续适用。
- [ADR 0021](../adr/0021-status-glow-session-indicator-alignment.md)：列表操作不标已阅；正文点按才标已阅。

本 spec 是以上默认入口与插队返回边界的最新产品约定。历史验收记录保留原样，不表示已覆盖本 spec 的实机行为。本次不新增 ADR、设置项、手势、页面选择持久化或混合列表。
