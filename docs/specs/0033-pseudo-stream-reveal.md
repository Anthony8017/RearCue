# Spec 0033：完整到达内容的伪流式显现

日期：2026-10-11。
状态：grill-with-docs Q1–Q21 已收口，机主确认并要求实施；两处手机界面已接入，实机验收待补。
术语沿用 `CONTEXT.md` 的 Agent Mirror、Remote Codex Conversation、Final Reply、Turn Process、Pseudo-stream Reveal、Session Read State 和 Voice Broadcast。

## 目标与边界

四个可镜像来源的手机背屏 Agent Mirror，以及手机主屏 Remote Codex Conversation，均优先显示来源真实到达的文本增量。来源只能一次提供完整新内容时，对可见的新内容做快速渐次显现，避免整段突然出现；这只是**收到之后的阅读效果**，不会提前收到文本，也不得作为真实增量、生成中或链路速度的证据。Claude Desktop Chat 标签仍不镜像，主屏不新增非 Codex 来源的对话页。

本 spec 反转 spec 0026“不伪造逐字效果”的显示禁令，但不反转其获取真实增量的目标。桌面 Codex 仍可能整条到达；不能用伪流式宣称已解决到达延迟，能力边界须在验收记录中分清。界面不加常驻“伪流式”标签。

## 显示规则

1. **触发**：当前屏幕、会话、正文处于可见阅读状态，且正式回答、思考过程或工具摘要以整条新文本到达时才渐次显现。真实增量到达后立即显示，不额外缓冲；已有片段后补全文时只接续未显示的新片段，绝不从头重播。进度说明若归入本轮过程的文本，按思考/过程文本处理；提问、错误、批准结果、待答问题、耗时及用量等不播放，立即完整显示。
2. **节奏**：收到后立即开始；普通文字按字渐显，代码、表格、链接、Emoji 等按最小可读单位显现，不呈现破碎结构。长回复自动提速，一条内容约两秒内完整显示。合格条目按原有时间顺序排队，不能互相覆盖；多条连续到达造成积压时加速或跳过尚未播放的效果，尽快追上最新内容。错误、批准和待答等即时条目不等待动画，原有数据顺序仍不改。
3. **阅读与重入**：历史内容直接显示全文，不补播。手动回看时不打断或拉回最新；返回实时跟随、切换会话再回来、离开对话页或背屏不可见后重新进入时，已经到达的内容直接显示全文。进入不可见状态即停止效果，不在后台继续排队补播。
4. **点击**：主屏 Codex 对话正文点击可立即揭示全文。背屏正文点按保留原有切内容页及已阅回执语义，**不**为跳动画截走；切回来直接显示全文。标题、会话列表、过程展开/收起及远程批准的现有手势不变。
5. **完成与播报**：来源完成、Session Read State、Agent Alert、Voice Broadcast 及其回屏/跟随不等动画；语音播报开始时显示完整原始回复。播完动画本身不触发完成、已阅或通知。系统动画开关不控制此效果，关闭系统动画时仍播放。

## 验收

- 四源分别核对真实增量与整条到达；主屏 Codex 和背屏相同内容类型遵循相同规则，日志明确区分真实到达时间与显现时间。
- 长文本、代码、表格、链接及 Emoji 可读且约两秒内完成；突发多条内容不使画面长期落后，顺序及最终原文不丢、不重、不改。
- 真增量接整条、回看、切会话、熄屏/离页后重入、背屏点按切页、主屏点击跳过、过程折叠逐项回归。
- 错误、批准、待答、完成提醒与语音播报不被动画拖延；关闭系统动画仍按本 spec 显现。Detail View、通知页、Session Picker 的版式和交互不变。

实施回填：手机侧共享显现控制器以桥条目 `entryId` 和 `open` 区分整条新内容与真实增量；背屏使用实时流作观察基线、回看快照作显示基线。主屏 Codex 正文仅在播放期间响应点按揭示，背屏原有点按切页与已阅语义保持。桥协议、来源适配器及生产 `RearCueBridge` 均未改动。

验证：在最新主分支上 `gradlew test :app:assembleDebug :rear:assembleDebugAndroidTest :app:assembleDebugAndroidTest` 已通过；显现控制器的 JVM 判例覆盖历史、增量、积压、回看与结构化文本。定向 `AgentProcessFoldUiTest` 实机运行首项长时间未结束（3 项中 0 项完成），为避免持续占用设备，主动停止隔离测试进程，故 AndroidTest 结果为未验而非通过；四源真链路及人工画面验收、来源时序日志证据仍待补。此效果是可调整的阅读策略，不另立 ADR。
