# Spec 0024：Remote Codex Conversation（issue #285）

状态：已实现；2026-10-06 机主确认全部采用推荐，扩为主屏二级对话页。
术语采用 CONTEXT.md 的 Remote Codex Conversation、Agent Mirror、Remote Approval、Agent Alert、Session Lock。
本 spec 将 ADR 0009 的「发 prompt 永不做」部分反转；任意按键、文件管理与任意电脑控制仍禁止。

## Problem Statement

Codex 经 ccswitch 切换 provider 后，外部远程新建会话可能把第三方模型配到 ChatGPT 执行账号上，
首轮即失败；RearCue 只读镜像只能看到失败结果，不能主动选择项目/可用模型、重试或收口失败空会话。

## Product Scope

- 单电脑、手机主屏、Codex 单来源；背屏继续只读与 Remote Approval。
- 主页保留「Codex 对话」入口，进入独立二级页；新建、切换会话、停止和失败空会话删除集中在该页。
- 二级页显示当前会话的完整问答历史，本轮过程沿用 spec 0028/0030 的可折叠呈现；底部固定输入框与发送按钮，键盘弹出时保持可操作。
- 会话选择使用顶部标题触发的会话列表，模型与项目菜单必须贴近各自按钮；切换主屏对话不改变背屏 Session Lock。
- 首次进入优先最近浏览的有效 Codex 会话，再回退当前 Codex 会话或名册第一条；无会话时保留新建入口。
- 各会话草稿独立保存。回答中允许写草稿、禁止发送；手机承载的回合可立即停止，电脑承载的回合明确提示在电脑端停止。请求发出即显示发送中并禁止连点，失败与状态未知均保留草稿。
- 支持新建、对所有在册 Codex 会话继续追问；正常会话只在电脑端归档。
- 输入仅文字与粘贴；不做语音、图片、文件、成本预测、多电脑选择或离线队列。
- 项目默认最近使用项，只允许选择电脑上的可用项目。
- 模型默认「自动」；手动模型仅当前会话有效，只显示当前可用模型，中途不可用必须询问。
- 空闲会话仍由电脑承载时，「自动」沿用电脑会话模型进行即时投递；明确手选模型时提示切回自动，不得悄悄忽略选择。
- 发送后进入实时会话；不抢占手动 Session Lock，自动档沿现有仲裁。
- Codex 单写入方按回合顺序交接：RearCue 发起/追问期间持有会话，回合完成、停止或失败后立即释放；
  随后 Codex 桌面端可正常继续。桌面仍持有空闲会话时，由该持有者接收手机追问，确认实际接收才回已发送；忙时不投递、不排队，不抢占、不自动重试。
- 发起/停止要求手机已解锁；发起不预批准文件修改或命令执行。

## Failure And Lifecycle

- 断线禁止发送，不排队。
- 发送状态未知时绝不自动重试；提供查看与手动重试，重试前提示可能重复。
- 明确拒绝与失败不能显示为发送状态未知；电脑未及时接收时撤回未消费的投递项，只有确认撤回后才报明确未发送，否则维持未知态。
- 切换会话后，旧请求的回执只能更新旧会话的发送状态与草稿，不得清空新会话草稿。
- 失败空会话保留「发起失败」状态，可换可用模型后重试或二次确认真删除。
- 删除仅适用于失败且无正常回复的会话；正常会话不得从手机删除/归档。
- App 退出不终止电脑任务；完成、失败、等待确认复用 Agent Alert，点通知直达会话。

## Security

- 公共隧道上的发起、追问、停止、删除和远程批准必须携带 PC 桥访问凭据。
- 访问凭据只证明 RearCue 端点可达，不替代手机解锁门槛。
- Codex 的文件/命令批准仍逐项发生；不得使用自动批准或危险旁路完成远程任务。

## Acceptance

1. provider/model 不匹配在创建前被阻止或由当前 provider 的模型列表解决。
2. 新任务创建后可在手机和电脑同一列表看到；首轮结束后电脑端可继续输入；失败空会话不再出现「手机有、电脑无」的不可解释状态。
3. 手动锁定、离线禁发、无自动重试、失败重试/删除、顺序写入交接和通知直达均按 Product Scope 生效。
4. 文件修改与命令执行仍产生批准请求，拒绝后任务继续但不执行该动作。
5. 主屏进入独立对话页，能切换会话、查看完整历史、展开过程；输入与发送在键盘上方，会话/模型菜单位置正确。
6. 连点只发一次；回答中保留草稿；明确失败、桌面占用、未知回执和切会话期间的回执均按 Failure And Lifecycle 处理。
