# Spec 0031：背屏选项作答与待答提醒不自动打开

日期：2026-10-06。
状态：2026-10-10 Q12–Q13 按推荐确认，最终范围已收口并实施：仅桥自己发起的 Codex 结构化选项题；逐题保存、整组提交。验证与部署见验收记录。
术语沿用 CONTEXT.md 的 Pending User Question、Remote Approval、Session Picker、Agent Alert、Voice Broadcast。
修订 spec 0027 的「新题自动打开」与「首期仅电脑回答」；其他边界待本轮及后续问答确认。

## 用户要求与已确认决定

- 用户要求：不自动打开待答问题，能够在背屏选择题目提供的答案选项。
- Q1：既有绿色提示、通知、震动与语音继续服从现有设置；新题到达和读题播报均不自动切换背屏页面。
- Q2：本次只修改 Codex；其他来源保持现有体验。
- Q3：先选答案，再点提交；点选本身不向电脑发送。
- Q4：全部答完后留在该会话，查看其继续输出。
- Q5：会话正文顶部显示「待答 N 题」按钮，手动点击进入答题；新题不替换正在看的正文。
- Q6（由 Q13 修订）：逐题选择并保存，最后明确提交整组；只有来源回执确认后标为已提交并回该会话正文。单选或多选遵循原题声明。
- Q7：没有选项的题显示「请在电脑回答」；本次不增加背屏文字输入。
- Q8：主屏锁着时允许背屏提交，仍须选好答案再点「提交」。
- Q9：离开答题或桥断线后保留未提交选择；同题有效时继续，过期或电脑已答后清除，不自动提交。
- Q10：提交结果不明时保留选择并显示「提交状态未确认」，核实后由机主手动重试，不自动重发。
- Q11：Dashboard 不在背屏时，不因新题唤醒或抢回，只按既有设置提醒；机主手动打开后进入待答。
- Q12：只开放由手机通过 PC 桥发起并由该桥持有请求的 Codex 题目；普通 Desktop 题提示「请在电脑回答」。
- Q13：背屏逐题保存，最后统一提交；已保存不等于来源已收到。
- 待答问题仍是独立于任务运行状态的事实，不等于文件修改或命令执行批准。

## 沿用与实现必须处理的边界

- 点选与提交分开；提交期间禁重复点击；题目及长选项完整可读。
- 电脑与背屏同时处理时以题目真实状态为准。已答、已解除、过期的题不能继续提交，不把它们伪记为背屏答题成功。
- 本轮结束、停止或换轮沿 spec 0027 的真实生命周期解除题目；普通输出不清题。电脑端单独跳过的即时同步仍按已记录限制处理。
- 使用既有 PC 桥访问保护，不放宽到普通文字输入、预批准文件/命令或其他来源的新动作。
- 语音队列、媒体键、真正批准的三处入口及完成结果的回屏规则沿既有口径；答题按钮不误触发页面空白手势。
- 桌面接入或某题型不可可靠支持时明确提示「请在电脑回答」，不能把按钮显示当成已支持真实作答。

## 当前事实与验证要求

证据与尚未验证的边界见 [只读调查](../research/codex-rear-question-reply.md)。

- 现行待答问题规格为只提醒、电脑作答；背屏当前可展示题目和选项文字。
- 当前生产桥的 Codex 同步提问只采集题目，尚未保留可回复请求；Codex 的现有动作入口不能提交选择题答案。
- 普通 Desktop 异步问题与桥自身 app-server 的问题属于不同接收路径，须分别验证真实答复与逐题解除。
- 当前 Desktop 安装包中已找到路由到实际会话拥有者的候选答题入口，本机对应通信通道存在；这是只读源码与环境证据，尚未连接、注册或实际提交。
- 当前 Desktop 异步答题界面已证实为单选；多选只在其他共享组件出现，不能据此声称异步题支持多选。原题语义必须可核实，不能把无法支持的题型悄悄改成单选。
- 当前 Desktop 正常界面通常收齐多题后一起发出；逐题答复标记和未答题保留可观察，但每题单独提交仍需隔离实测。
- 背屏提交必须对应当前仍有效的具体问题；不得将普通追加文字或文件/命令批准误当作答题成功。
- 设计收口前不修改运行代码、不构建装机、不重启生产桥。

### 实际接入验证的新约束（2026-10-06）

- 本机 IPC 连接、自定义客户端注册、真正 owner discovery 和只读当前回合快照已实测成功；未发送答复、修改 Codex 程序或操作真实会话。
- 普通 Desktop 的 follower steer 在回合不匹配时会自动使用新回合重试。外部接口不读取调用者的 expectedTurnId，也不接收内部 JavaScript 请求校验回调；提交前查询快照不能形成原子护栏。
- 其他已核外部通道没有专用异步逐题答复或 raw app-server 转发；native send-message 工具是普通对话提交且缺少目标回合约束，不能替代安全答题。
- 同步问题的响应会解除整个原始请求，不具备已验证的逐题立即生效语义；可靠方案为逐题保存，整组收齐后一次发送。
- 不使用已知会自动跨轮重试的 Desktop 写路径，不把界面出现按钮当作真实回写成功。

## 已确认行为的验收目标

- Codex 新题到达时，列表、通知页、正文及正在回看的位置均保持；只更新绿色待答提示并按既有设置通知或朗读。
- 读题播报不打开题目、不改会话选择、不触发结果播报回屏；其他完成结果的播报规则不变。
- 点选答案只改变本地选择，明确提交动作才发送；提交归属于具体会话、回合与题目。
- 手动点击「待答 N 题」后展示题目与完整选项；逐题选择并保存，最后提交整组，无选项提示电脑回答。
- 主屏锁屏时依然可在背屏选好并提交；保存不代表已发出，整组提交获来源完成证据后才解除。
- 全部题目成功答完后留在当前会话，真正批准仍走既有独立链路，其他来源不变。

- 新手机会话注册 `rearcue_choice_question` 动态工具；不改工作模式或文件/命令批准策略。同步标准提问也接入同一请求身份保护。

- 背屏提交按钮固定于可见区域，长题/选项在内容区滚动；题目及选择保留到权威名册确认失效。
