# Spec 0009：背屏视觉打磨（充电水位 + 细体数字右下 + 弥散光晕 + Detail 全屏去应用名）

状态：已与机主 grill 收口（2026-09-27），frontier 空，全部按推荐定案。
本 spec 显式反转 spec 0008 的两处验收（相机带不染色 → 全屏覆盖；白描边 → 弥散光晕），见 Further Notes。
触发：机主对 spec 0008 实机效果提出 5 条视觉反馈。

## Problem Statement

spec 0008 落地实机后，机主对四处视觉不满意：①充电视觉——绿色填充避开相机带显得小气，纯渐变平面质感差，要求做成「水」并强化质感；电量数字用系统默认粗体、顶部居中，不好看且与 Icon Set 抢视觉中心，要求换好看的字体并放右下角。②图标外围「发光」实现成了贴边实心描边圈，观感廉价像描边。③Detail View 应用名与通知标题重复显示两遍（IM 的通知标题常即应用名/会话名）。④Detail 卡片虽已占满内容安全矩形，但避开相机带与圆角，正文窗口实际仍显小。

## Solution

三组视觉打磨，全部在既有 Dashboard 视图内，不动任何投送/门控/状态语义：

- **充电视觉改「水位」隐喻**：绿色水铺满整个背屏（**含相机带**），水面高度＝电量比例，水面轻微荡漾（安静的微波，非 3D 重力液体、无气泡）；上缘微光保留；电量数字挪到**右下角**、换**现代细体**（初选 Outfit Light，OFL 开源；备选 Manrope Light——实机不满意换字体文件即可）；充电中来的通知照常浮在水面之上显示；Icon Set 图标以白色光晕保持可见。
- **图标强调从描边圈改弥散光晕**：通知高亮（暖白）与充电态（白）两处强调统一改为从图标向外弥散渐隐的多层光晕，不贴边、无硬轮廓；颜色语义不变。
- **Detail View 全屏化**：卡片铺满整个背屏（含相机带）；**应用名整行删去**（含那行的小图标），直接通知标题＋正文；正文完整显示、超长滚动；弹性展开等过渡动效不变。

## User Stories

1. 作为机主，充电时我希望绿色「水位」铺满整个背屏、不避相机带，以便视觉完整大气、不再显得刻意留白。
2. 作为机主，我希望水面高度对应电量比例，以便瞥一眼即知大概电量。
3. 作为机主，我希望水面轻微荡漾、有水的质感，以便不是一块死板的绿色平面。
4. 作为机主，我希望微波安静不抢注意力（无剧烈波动、无气泡），以便桌上充电时背屏不闹。
5. 作为机主，我希望电量数字挪到右下角，以便不与 Icon Set 抢视觉中心、构图更稳。
6. 作为机主，我希望数字换成现代细体、大字号下高级耐看，以便背屏有高端系统电量般的观感。
7. 作为机主，我希望充电中来了通知仍照常显示、浮在水面之上，以便充电与通知互不打架。
8. 作为机主，我希望充电时 Icon Set 图标在水上仍清晰可辨（白色弥散光晕），以便充电不丢「谁在等我」。
9. 作为机主，我希望右下角数字在绿水与微波之上保持清晰可读，以便远近都一眼可读。
10. 作为机主，我希望实机字体观感不满意时只换字体文件即可（备选已定），以便调整零成本。
11. 作为机主，我希望新通知高亮的图标光是向外弥散渐隐的光晕而非贴边描边圈，以便质感高级不廉价。
12. 作为机主，我希望充电态非高亮图标的白色强调也用同一语言的光晕，以便两种强调风格统一。
13. 作为机主，点开详情我希望卡片铺满整个背屏（含相机带），以便正文显示空间最大化。
14. 作为机主，我希望详情不再显示应用名（它常与通知标题重复成两遍），以便信息干净。
15. 作为机主，我希望去掉应用名后那行小图标也不留、直接标题＋正文，以便版面干净（机主定案）。
16. 作为机主，我希望详情显示完整通知正文、超长滚动，以便不必翻主屏看全文。
17. 作为机主，我希望常态仍是纯 Icon Set（无时间、无横幅），本轮只改视觉不动结构。
18. 作为机主，我希望充电动画触发/退出/总开关语义不变（插电独立触发、拔电∧Icon Set 空即退、默认开）。
19. 作为机主，我希望呼吸语义不变（约 3 秒、30 秒冷却、看过即熄/清除即熄、快照重建不呼吸）。
20. 作为机主，我希望 Detail 交互不变（再点收起、所示通知清除自动收、打开即冻结最新一条、弹性展开保留）。
21. 作为机主，我希望 DND Follow / Posture Gate 等门控语义不变，本轮完全不碰投送链路。
22. 作为机主，我希望水波动画只在充电展示期间运行、不显著发热耗电，以便整夜充电无顾虑。
23. 作为开发者，我希望「电量百分比×屏幕尺寸×相位 → 水面路径与填充范围」是纯函数，以便 JVM 单测锁死几何语义。
24. 作为开发者，我希望动效渲染（微波、光晕、展开）不写 JVM 测试、以实机验收链替代（沿 0008 判例），以便测试只测决策不测渲染。
25. 作为开发者，我希望水波参数（波幅/周期）、光晕层参数、字体全部走 DesignTokens 语义令牌，以便不散落硬编码。
26. 作为开发者，我希望验收轮留痕 poc-logs（E 系列惯例）：全屏覆盖含相机带、微波肉眼可辨且安静、右下细体数字、光晕弥散无硬边、Detail 全屏无应用名全文可滚、充电中通知叠加、呼吸/门控/拔电回归。
27. 作为开发者，我希望 `gradlew test` 既有基线 0 失败不回退。

## Implementation Decisions

- **模块改动**：`:rear` 几乎全部（充电填充层全屏化＋水面波、数字右下细体、描边圈→弥散光晕、Detail 全屏落位＋去 header 行）；`:core` 无语义改动（本轮全是视图层）；DesignTokens 增补字体/水波/光晕令牌；`:app`、`:notification` 不动。
- **充电填充层**：填充起点从内容安全矩形左缘改为屏幕全宽——**相机带不再避让**（反转 spec 0008「相机带不染色」验收项）；水位语义不变（percent coerce 0–100、自底部向上）；层级不变（背景层，压呼吸层之上、全部内容之下）。
- **水面质感**：保留既有垂直渐变主体（bright→deep）；上缘直线亮边改为复合正弦表面路径（波幅约 3–5px、周期 8–12 秒量级、慢相位漂移），上缘微光随波面走；**不做** 3D 重力液体、气泡、交互水（CONTEXT.md Avoid 钉死）。动画帧驱动只在充电在屏期间持续；实现期以实机帧率/发热观察收口。
- **数字**：右下角落位（避让屏幕圆角，以运行时圆角半径为准）；白字、字号量级维持 60sp 上下；字体打包 OFL 授权的可变字体 **Outfit**（以 Light 权重渲染；备选 Manrope Light，仅换文件无逻辑耦合）。细体只用于充电大数字——Detail 文本（15–17sp）保持系统字体，小字号细体可读性差。
- **光晕**：两处双层描边圈（高亮暖白、充电白）统一改「多层弥散」：外层大半径低透明度→内层紧贴渐隐（多层圆角矩形渐变模拟 blur，不依赖 RenderEffect）；颜色沿用 highlightWarm 与白；呼吸层（整屏径向光晕＋边缘微光）不动（0008 已验收的呼吸观感）。呼吸层中心现为避相机带略偏右，全屏时代价不成立——实现期复核回中。
- **Detail View**：落位从内容安全矩形固定尺寸改为全屏（含相机带；底色 detailSurface 不变，圆角随屏幕）；**header 应用名整行删除**（含 20dp 小图标）；正文自标题下延展至屏底完整滚动；过渡动效（transformOrigin 自点按图标、spring 展开/收起）不变；触摸判定随卡片同步放大。
- **CONTEXT.md**：Charging Animation / Detail View / Dashboard 三词条已随 grill 定案改写（工作树内），实现随本 spec 一并入库。

## Testing Decisions

- 好测试只测输入→输出。本轮唯一有决策的纯逻辑：水位几何（percent×屏尺寸×相位 → 表面路径与填充范围）抽纯函数进 JVM 测；其余全是渲染，不写 JVM 测试、以实机验收链替代（沿 spec 0008 story 25 判例）。
- Prior art：`DisplaySafeAreaTest` 的几何纯函数判例（同风格）、spec 0008 实机验收链＋poc-logs 归档惯例。
- 实机验收场景＝story 26 清单；基线 `gradlew test` 0 失败不回退。

## Out of Scope

- 3D 重力液体、气泡、摇晃交互水。
- 波动强度/配色/主题等任何设置项（固定一套精心设计的样式）。
- Detail 文本换字体（仅充电大数字换）。
- 通知监听/投送/保活/门控/呼吸语义的任何改动。
- 多条堆叠、历史回看（永不实现）。
- 充电数字以外的信息（功率、充满时间等）。
- 主屏 App（设置页、Allowlist）改动。

## Further Notes

- **spec 0008 反转留痕**：反转一＝充电填充避让相机带→全屏覆盖；反转二＝Icon Set 白描边→弥散光晕（充电白圈与高亮暖白圈同改）。0008 其余判例（触发/退出/门控/呼吸/验收链）继续有效。
- grill 判例：充电数字现状为**顶部居中**（系统默认粗体），机主口述「在右下角」经代码核实为期望落位而非现状描述。
- 「应用名两遍」根因：header 的 resolveLabel＋通知标题（Notification extras title，IM 常即应用名/会话名），无去重逻辑；定案＝删 header 整行，标题承载来源。
- ui-ux-pro-max（机主称「UI Taste」）的查询工具在本会话不可用；字体与质感判断按其规范底线（语义令牌、对比度、动效克制）人工执行，实现期工具可用时可复核。
