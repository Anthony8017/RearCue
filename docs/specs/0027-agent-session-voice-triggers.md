# Spec 0027：主会话可见范围与语音播报触发

状态：grill-with-docs 已定案（2026-10-05，Q1–Q7，frontier 空，机主最终“确认”）；已实现，当前只作本地验证，统一装机验收待协调聊天完成。
术语沿用 `CONTEXT.md` 的 Agent Mirror、Session Picker、Waiting-for-Approval、Agent Alert、Voice Broadcast、Broadcast Pause、Broadcast Discard。
相关规格：[Spec 0022 / #273](https://github.com/Anthony8017/RearCue/issues/273)。本次取代其中“等待不播报、进入等待清空队列”的规定；其余设置、引擎和耳机控制继续按现有定案。

## 问题

内部子 agent 被当作用户会话处理；部分 Codex 子 agent 还会污染主会话正文与完成状态。播报以工作中变为空闲代替真实完成事实，导致停止和历史回放也可能被朗读。需要用户回答或批准时，反而只清空播报队列。

## 已答规则

### 会话可见范围

- 主屏和背屏会话列表只列用户主会话，四来源统一适用。
- 内部子 agent 不作为可选会话，不直接产生 Agent Alert 或 Voice Broadcast；其状态、正文和完成不得覆盖主会话。
- 子 agent 的内部提问由主 agent 处理；确需机主回答时，由主会话明确转交。主会话主动提供的结果照常按主会话规则呈现。
- 已有 Notice Line 规则继续有效：主会话里的子任务通知保持低强调，不冒充回答或播报内容。

### 播报触发

| 事实 | 目标行为 |
| --- | --- |
| 主会话产生本轮真正完成的新结果 | 按已有完成规则朗读；真实完成且无文字回复时保留已有固定提示 |
| 主会话最终失败、不能自行继续 | 朗读“任务失败”和简短原因 |
| 主会话明确需要机主回答、拍板或批准 | 产生一条待答播报；不清空已有结果 |
| 任务手动停止、取消、普通空闲更新 | 不当作完成播报，不借用上一轮回答 |
| 工具局部失败、自动重试、内部子任务事件 | 不当作整项任务失败或完成播报 |
| App 重启、桥地址变化、重新连接时的历史回放 | 恢复界面与当前状态，已发生过的完成/失败不补播 |
| 同一请求或结果重复送达 | 只播一次 |
| 实时输出、思考、工具日志、客套追问 | 不单独触发播报 |

“需要机主处理”可与 agent 继续做其他工作同时存在；继续工作本身不代表问题已解决。

### 问题内容与队列

| 决策 | 机主选择 |
| --- | --- |
| Q1 提问范围 | 只播确实需要机主处理的事项，不为客套追问单独播报 |
| Q2 朗读内容 | 会话名＋问题和选项；批准请求读简短摘要 |
| Q3 当前正在播旧结果 | 播完当前整条结果，再播问题，不中途打断 |
| Q4 还有旧结果排队 | 当前整条结束后先播问题，再播剩余结果 |
| Q5 播到前已经回答或撤回 | 自动跳过 |
| Q6 未答重复催促 | 同一问题只播一次，不定时催促；新问题另行播报 |
| Q7 问题播完仍未答 | 照常播后续结果，待答问题仍在界面保留，不重复催促 |

- 多个有效待答事项按到达顺序排列；现有结果队列保留。
- 主动暂停仍保留队列，新问题排队等待；恢复后遵循上述顺序。耳机双击停止清空和“下一首”跳过规则继续有效。
- 已在来源端处理的事项应结束待答状态；已归档会话和失效请求不产生新的播报，排队中的待答内容也应撤销。
- 普通回复中的问号、疑问词或引用不能独自证明需要处理。没有可靠待答事实时，正文继续作为普通回答按已有完成规则朗读，不虚构等待状态。

## 采集边界

- Codex 结构化提问、权限批准与来源显式等待均需覆盖；异步提问的 `{accepted:true}` 只代表请求已受理，不能视为机主已回答。
- 完整问题与选项应来自该次请求，不能拿最近回答或一行截断摘要冒充；多题应完整保留。
- 能力不足的来源应如实记录限制，不承诺仅凭自然语言准确区分必须作答和可选追问。
- 对子 agent 的排除应依据来源身份及父子关系，覆盖在册快照与活动增量；不能只在手机列表层隐藏。

## 已核验事实

2026-10-05 只读审计；未停桥。以下是代码路径及本地样本结论，未作手机实际发声复现。

| 问题 | 证据与边界 |
| --- | --- |
| 子 agent 污染主会话 | 两个本机 Codex rollout 的 `source.subagent.thread_spawn` 明确标识子身份，`session_id` 指主会话、`id` 才是子会话；[codex.mjs](../../tools/bridge/adapters/codex.mjs) 优先取前者且不排除子身份。运行桥该文件与本工作区内容一致 |
| 停止也播完成、可能念旧回复 | `turn_aborted` 归入 idle；[VoiceBroadcastPolicy.kt](../../app/src/main/kotlin/com/rearcue/poc/voice/VoiceBroadcastPolicy.kt) 将 working→idle 入完成队列；[RearCueApp.kt](../../app/src/main/kotlin/com/rearcue/poc/RearCueApp.kt) 取最近回答，不限定本轮 |
| 历史补播 | [BridgeRelayClient.kt](../../agent/src/main/kotlin/com/rearcue/poc/agent/BridgeRelayClient.kt) 每次 start 将游标归零，事件环历史仍经 onSession 进入播报。普通网络断线重连保留游标，不能笼统说所有重连均补播 |
| 局部失败误报任务失败 | [zcode.mjs](../../tools/bridge/adapters/zcode.mjs) 将工具错误变成会话 error，随后的工具结果又可回到 working；播报没有最终失败门槛 |
| 提问漏播 | Codex 两类 request_user_input 工具目前都归入 working；其他来源可归入 waiting，但现有策略只清空全局队列。真实异步提问样本及纯函数映射已核对 |
| 需要完整问题时数据不足 | Claude 等待 hook 未完整保留摘要；ZCode 问题/选项信息有缺；DSH 只取第一题且摘要截断。必须补齐数据才能满足 Q2 |

潜在风险，尚未复现实际重复发声：Codex notify 与 rollout 完成没有回合级去重；播报队列缺少会话与回合身份，难以定向移除归档后的排队内容。实施时需补判例，不把风险写成已复现故障。

## 验收范围

- 子 agent 新建、运行、结束均不入用户列表；不会覆盖主会话正文和状态；不会触发内部完成播报。
- 真正的新完成/最终失败保持原有播报；停止、旧历史和可自行恢复的工具错误保持安静。
- 需要机主处理的多题请求正确朗读会话名、问题及选项；批准请求读摘要；异步请求受理不提前解除待答。
- 当前结果完整播完后，待答事项优先于其他排队结果；已回答/撤回请求跳过，重复送达不重复播。
- 待答事项播完后，后续结果继续播；尚未回答的问题仍在界面保留，不因后续活动自动解除，也不重复语音催促。
- 重启、换地址、重新启用连接恢复界面但不补播旧完成；真正的新结果仍可播。
- 主动暂停、双击清空、下一首及小爱语音设置按既有定案回归；不把“等待”继续当作全局清空入口。
- 四来源按实际可观测能力验收；纯规则与协议判例通过后，手机实际发声验证并如实留证。

## 实施与集成边界

- 桥新增单事件 `voiceEvent`（稳定回合身份、正文、原始发生时间、回放标记）及当前 `pendingRequests`；会话状态变化本身不产生完成播报。
- 与待答问题聊天的 `pendingQuestions: [{id,title,options}]` 模型兼容：显式快照更新按原 ID 归一，空列表解除对应问题；语音请求不替代其视觉与交互政策。
- 连接先取得权威快照游标，历史页不进入语音队列；源端历史补读另有回放标记，当前快照中的有效待答可恢复。
- Codex 按 `source.subagent`，Claude 按内部行身份，ZCode 按 `sessionKind=subagent_child`，DSH 按 `header.origin=subagent` 排除子 agent；仅有父会话 ID 的普通 fork 保留。
- ZCode 无订阅事件的降级模式、以及其他来源只有普通 idle 的观测，继续提供镜像但不猜完成；Claude、DSH 的真实完成采用各自明确结束事件。缺乏请求身份或解决信号的旧来源无法承诺精确撤回，按实际能力记录验收限制。
- 统一合入 PR #311 时保留 `VoiceBroadcastSource`、原文句锚、按句跟随及媒体键行为。问题优先只作用于下一条选取，不打断当前整条；等待批准不清结果语音。
- 按验收协调消息，本聊天不安装 APK、不操作手机、不部署或重启生产桥。完成本地测试后提供提交号，由协调聊天统一构建并实机验收；设备听感和实际媒体键行为暂未验证。
