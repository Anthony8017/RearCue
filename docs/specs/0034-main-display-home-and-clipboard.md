# Spec 0034：主屏主页归位与重装首次自动连接

日期：2026-10-13
状态：产品取舍已确认；主页归位与当前剪贴板自动连接已有本地实现；重装首次启动强制检查待实现。实机验收与两端部署未完成。

## Problem Statement

机主打开主屏 APP 时，需要迅速判断服务与电脑连接是否正常，并进入常用内容。原主页将通知、状态、会话、连接配置、显示参数、提醒、语音与开发者选项混在长滚动页面内，常用入口难找，部分信息重复出现。

连接地址来自电脑复制的可连接桥地址。当前剪贴板内容可能相同、已经尝试过，重装或恢复数据后，旧去重记录可能让首次启动跳过自动连接。机主希望重新安装后第一次打开 APP 就自动检查一次，无需再复制相同链接或点重试。

机主也希望利用输入法历史中的桥地址。本机现有历史接口限制调用身份，RearCue 与现有 Shizuku shell 均不能直接读取。机主已接受保留微信输入法，由自己从历史中选条目复制，再交给 APP 自动验证连接。

## Solution

- 主页固定一屏，不滚动，只放背屏服务摘要、唯一实时电脑连接状态、待处理会话数量，以及「通知」「Agent 会话」「Codex 对话」「设置」四个入口。
- 通知与 Agent 会话分别进入二级页；Codex 对话沿用现有二级页。配置、参数与开发者选项统一进入设置。
- 同一事实只在负责该用途的位置显示。主页给综合结论，运行与权限给组成事实，开发者选项保留独有诊断；连接验证结果不冒充实时连接状态。
- 镜像开启且未连接时，APP 在主屏前台获得焦点后检查当前剪贴板。历史条目由机主在微信输入法中选中复制，APP 不自动遍历历史。
- 先筛选可连接桥地址的格式，只有符合格式的候选才进入联网验证。验证桥身份和访问凭据通过后，才保存并启动连接。
- 重装后的首次主屏启动强制检查当前剪贴板一次，不被恢复的旧去重记录或与当前地址相同的判定拦住。普通启动仍按去重规则处理。
- 「一次」指一次内容检查；符合格式时最多进行一次连接验证。失败保留原配置，不循环验证。同一安装期的重复页面进入、焦点变化或状态刷新不重复消费这次机会。
- 真正连接成功才简短提示「已自动连接」；验证失败只在连接配置处给原因。

## User Stories

1. 作为机主，我希望主页内容一屏可见，以便不用滚动寻找常用入口。
2. 作为机主，我希望主页显示背屏服务的综合状态，以便迅速判断是否需要处理。
3. 作为机主，我希望异常提示占用固定位置，以便异常出现时主页仍保持一屏。
4. 作为机主，我希望点状态摘要进入运行与权限详情，以便查看原因并处理。
5. 作为机主，我希望实时电脑连接状态只出现一处，以便不会被重复或过期的状态误导。
6. 作为机主，我希望从电脑连接状态进入连接配置，以便快速修改地址。
7. 作为机主，我希望主页显示待处理会话数量，以便知道是否有事项需要回应。
8. 作为机主，我希望从主页进入通知二级页，以便查看通知应用与下拉栏可见通知数量。
9. 作为机主，我希望从主页进入 Agent 会话二级页，以便查看统一会话列表并选择 Session Lock。
10. 作为机主，我希望会话行下提供既有 Remote Approval 操作，以便处理等待事项且不重复列出同名会话。
11. 作为机主，我希望从主页进入 Codex 对话二级页，以便继续使用现有对话功能。
12. 作为机主，我希望上述二级页都能返回主页，以便页面层级清楚。
13. 作为机主，我希望连接地址和 Agent Mirror 总开关归设置，以便主页只留重要内容。
14. 作为机主，我希望亮度、提醒、震动、语音、批准开关、充电动画与姿态门控都在设置，以便统一调整偏好。
15. 作为机主，我希望开发者选项归设置且默认收起，以便保留自查入口而不挤占主页。
16. 作为机主，我希望设置不会重复会话列表与 Codex 对话入口，以便同一功能有清楚的位置。
17. 作为机主，我希望保留微信输入法，以便不改变日常输入体验。
18. 作为机主，我希望从输入法历史选中并复制桥地址后，APP 能自动识别当前内容，以便无需再手填连接地址。
19. 作为机主，我希望先筛选链接格式，再进行联网验证，以便普通文字和无效链接不会触发网络检查。
20. 作为机主，我希望仅带有效形状的访问片段的可连接桥地址参与验证，以便普通网站或裸域名不会被保存为电脑连接。
21. 作为机主，我希望 APP 前台未连接时检测新的剪贴板内容，以便复制新地址后能接上电脑。
22. 作为机主，我希望重装后第一次打开 APP 自动检查一次当前内容，以便旧去重记录不会挡住首次连接。
23. 作为机主，我希望首次机会等配置加载和页面获得焦点后再判断，以便初始化顺序不会让检查提前失效。
24. 作为机主，我希望重复打开页面和重复获得焦点不会反复触发首次检查，以便不会重复探测。
25. 作为机主，我希望关闭镜像后 APP 不自动开启它，以便保留我的开关选择。
26. 作为机主，我希望已连接时 APP 不读取或导入其他地址，以便不会自动切换电脑。
27. 作为机主，我希望验证确认桥身份和凭据后才替换配置，以便不可达、错误凭据或普通网站不会覆盖旧地址。
28. 作为机主，我希望失败后保留原配置且不循环验证，以便连接设置可继续使用。
29. 作为机主，我希望验证失败原因只在连接配置显示，以便主页不堆积提示。
30. 作为机主，我希望相同内容不会自动重复验证，而新内容或手动重试可以再次检查，以便在需要时主动重试。
31. 作为机主，我希望修改地址、关闭镜像、链路恢复或复制其他内容后，旧验证结果不能写回，以便新选择不会被慢请求覆盖。
32. 作为机主，我希望 APP 在链路真正连接后才提示成功，以便不会把验证通过误认为已经连上。
33. 作为机主，我希望默认字体、大字体与系统安全区下入口仍可见可点，以便主屏页面正常使用。

## Implementation Decisions

- 主屏展示与安装后首次检查归手机 `:app`；既有桥连接客户端与背屏状态事实继续共用，不另起一条连接链路。
- 主屏主页不使用长滚动布局。异常占用既有摘要位置，原因与处理下沉运行与权限。首页入口不重复显示列表、正文或参数。
- 通知应用数量、下拉栏可见通知数量在通知二级页显示；会话列表、Session Lock 与 Remote Approval 在 Agent 会话二级页显示。Codex 对话使用已有界面和行为。
- 设置集中通知名单、连接配置、Agent Mirror 开关、显示、提醒、语音、批准开关、充电动画、姿态门控与开发者选项。
- 手机仅在主屏 APP 前台且获得输入焦点时读取当前剪贴板。背屏 Dashboard、冻结唤醒页面与后台服务不作为读取入口。初始化时须先加载连接配置和总开关，再决定是否检查。
- 安装期首次判断应独立于内容去重。安装期状态不能被恢复的旧内容摘要误判为已经尝试；同一安装期的重复主屏生命周期事件只能触发一次强制检查。如何识别安装期由实现者在手机平台边界处理，不依赖剪贴板内容变化。
- 强制首次检查仍受「Agent Mirror 开启且桥链路未连接」条件约束；不自动开启镜像，不切换已连接电脑。普通重复打开 APP 不获得新的强制机会。
- 首次检查符合格式时最多验证当前候选一次，不循环尝试。既有桥客户端对已保存地址的正常自动重连行为继续沿用。
- 先筛选当前内容是否为完整 http(s) 可连接桥地址，主机可解析、不含用户信息、额外路径或查询参数，访问片段非空且无空白或控制字符。不从混合正文提取链接，不处理裸域名，不读取 URI 对应的其他内容。
- 当前可访问输入中只有一个候选。早期讨论的「自动读取历史、按复制时间由新到旧筛选与验证」已由后续确认的手动选择历史条目方案取代，不列为本次实现或验收项。
- 复用既有地址格式归一化、ClipboardBridgeImporter、地址持久化与桥客户端。首次条件作为已有导入入口的输入；避免为安装后检查复制另一套识别、验证和保存规则。
- 公共存活探测不足以验证身份与凭据。自动导入使用只读 GET `/connection/verify`，通过 Authorization 的 Bearer 凭据验证；成功响应声明 ok 为 true、product 为 rearcue-bridge、protocol 为 1，并禁止缓存。
- 手机限制响应大小、不跟随重定向；普通网站的成功 HTTP 状态、旧桥缺少端点、错误凭据及不可达均不能替换配置。验证接口不读会话、不触发动作、不改变手机在线事实。
- 新剪贴板内容、配置修改、开关变化或原链路恢复使旧验证结果失效。手动地址探测也不能把旧请求结果写回已更新的配置。
- 验证通过后保存并启动既有连接；等真实链路回调确认连接后才提示成功。失败保留旧配置，并只在连接配置展示原因。
- 内容摘要继续持久化用于普通自动去重，不保存完整输入法历史；凭据不在 UI 或日志中回显。首次检查和明确的手动重试可越过去重，但不能越过连接和开关条件。
- 手动保存、电脑 ADB 推送与背屏投送规则继续沿用。新增自动导入功能需要新手机 APK 与提供验证端点的新桥共同部署。

## Testing Decisions

- 以机主已确认的使用结果作为验收标准：格式优先、验证通过才保存、失败不覆盖、首次仅一次、总开关和已连接条件优先。验收行为与本轮 grilling 定案一致，无新增技术选型需要机主决定。
- 优先复用 ClipboardBridgeImporter 这一最高的自动导入行为测试入口；通过输入安装期、当前内容和连接事实，观察网络验证次数、保存结果及失效结果。不测试私有字段、源码布局或某个内部方法是否被调用。
- `:app` 的判例沿用当前完整桥地址识别、失败保留配置、跨进程去重、手动重试、已关闭/已连接不导入、异步旧结果失效及新内容优先等已有行为测试。
- 补齐重装首次判例：旧内容摘要恢复后仍验证一次；与已保存地址相同的候选首次仍可验证；重复进入与焦点变化不重复；新安装期可再检查；初始化未完成时不提前消费机会；首次检查失败不循环。
- 无符合格式的内容、缺凭据、混合文本、额外路径与查询参数时，验证请求数必须为零。已关闭镜像或已连接时也必须为零，并不改开关或地址。
- 网络契约沿用现有手机请求测试与桥 HTTP 行为测试：身份正确且凭据有效成功；无凭据、错误凭据、身份不匹配、过大响应、重定向、旧桥或不可达失败且不保存。
- 主屏页面以实机验证为主，不新增只镜像布局实现的 JVM 测试。核对一屏、四个入口、二级返回、所有设置写回、唯一实时状态，以及默认/大字体和系统安全区。
- 实机连接验收包含：重装后复制有效地址并首次启动、旧去重状态恢复、失败后再次打开、从微信输入法历史选条目复制、已连接时复制其他地址、镜像关闭时启动、验证期间改配置或复制其他内容。
- 使用隔离测试桥和指定设备完成验证；不得在清理或测试中硬杀生产 RearCueBridge。手机安装、生产桥更新与实机验收分别留证，不用单测或构建成功替代部署结论。

## Out of Scope

- 自动读取、遍历、排序或保存微信输入法及系统剪贴板历史。
- 修改默认输入法、读取输入法私有数据或借其他应用身份取得历史。
- 后台持续读取剪贴板、扫描剪贴板 URI、提取混合正文中的链接。
- 判断链接在电脑端的实际生成先后，或通过复制顺序声称它是电脑最后生成的地址。
- 无需机主选择就尝试历史中的多个电脑，或在已经连接时自动换电脑。
- 失败后的循环自动验证、自动开启已关闭的 Agent Mirror。
- 新的桥传输、Codex 对话写入方式、背屏投送策略、通知内容策略或输入法功能。

## Further Notes

- 本机为 Android 16，当前默认输入法是微信输入法。本机 HyperOS 历史接口虽有导出入口，但要求调用包等于当前默认输入法；现有 RearCue 与 Shizuku shell 不符合。调查未读取真实历史内容或凭据，也未修改输入法与手机设置。
- 机主先要求读取历史，随后接受「保留微信输入法，历史条目手动选中复制」的限制；本规格以这一最终确认作为范围。链接格式筛选继续先于任何联网验证。
- 本规格取代 spec 0005 的旧主页结构与设置范围、spec 0018 的主屏 Agent 设置区位置，以及 spec 0031 的连接状态与地址都放主页 Agent 卡顶部的位置约束；原状态文字、背屏状态标识和其他行为沿用。
- 主页归位、当前剪贴板导入、身份与凭据验证已有当前工作区实现；此前本地验证为 APP 191 项单测、桥 55 项行为测试、APK 构建和差异检查通过。尚无本次变更已合入或部署的证明。
- 重装首次启动的安装期记录与强制检查尚未实现，上述既有测试结果不证明该新要求已完成。不能把本规格发布视为代码实现或实机验收完成。
- 当前 APK 未安装到手机，生产桥未更新；后续执行仍需完成首次启动逻辑、相关判例和真实验收，按项目要求控制部署。
