# Spec 0011：背屏可读文字避让相机带 + Detail 阅读面修订（标题省略/右留空/纯黑底）

## Problem Statement

机主在实机点开背屏 Detail 正文、看 Agent Mirror 时发现一串体验问题：

1. **每行开头被相机模组吃字**——可读文字排进了背屏左侧的相机带（296px 全高挖孔带），内容画进带内就被相机模组物理挡住，一行字缺一截，Detail 和 Agent Mirror 都中招；
2. **Detail 第一行是废话**——通知标题恰好等于软件名时（如飞书那条），那行大字不带来任何新信息；
3. **版面偏挤**——文字让开相机带后右侧留空只剩一档小的，与左侧观感不平衡；
4. **底色不统一**——Detail 卡片是深灰，与整屏纯黑基调不一致；
5. **验收看不见根因**——实机验收判据是截图像素，而截屏截的是显存，物理遮挡在截图上完全不可见，问题因此长期漏网。

## Solution

把「可读文字」与「纯视觉背景」分成两条口径：

- **可读文字一律让开相机带**：文字左横跨收进安全区的静态布局框（含防烧屏漂移余量），左缘自动让到相机带右缘之外；右缘排满到距屏缘 8px、垂直位置进圆角弧区时自动外扩（**票 #97 修订**，原「两侧收进布局框」推翻右半边）；Detail 的标题/正文与 Agent Mirror 的状态/工作区/动作/回复同口径；纯视觉（Detail 卡底、充电绿水位、呼吸光晕）维持铺满含相机带（spec 0009「视觉完整」判例不反转）。
- **Detail 阅读面三处修订**：标题恰为应用名且正文非空时省略标题行（联系人/群名标题保留）；右侧留空提一档（本机 150px，与左侧观感平衡——**票 #97 已推翻：右距屏缘 8px 排满＋弧区外扩**）；卡底改纯黑与整屏一致。
- **验收补口径**：像素判读量坐标（文字落位、底色、留白），带内遮挡以布局坐标＋肉眼为准——截图判不了遮挡这件事本身写进词条与验收记录。

## User Stories

1. 作为机主，我希望 Detail 正文每行开头完整，以便不用猜被相机挡住的字是什么。
2. 作为机主，我希望 Agent Mirror 的状态标语、工作区、当前动作、回复原文每行完整，以便远程看清 agent 干到哪一步。
3. 作为机主，我希望通知标题恰是软件名时那一行不显示，以便正文第一行就是内容、不浪费版面。
4. 作为机主，我希望微信/QQ 的联系人或群名标题照常显示，以便知道是谁发的、在哪个群。
5. 作为机主，我希望正文为空时标题保留显示，以便卡片不会打开成一片空白。
6. 作为机主，我希望 Detail 右侧留空与左侧观感平衡，以便版面不显得文字被挤在右边。
7. 作为机主，我希望 Detail 底色纯黑与整屏一致，以便观感统一、AMOLED 省电。
8. 作为机主，我希望 Agent Mirror 与 Detail 用同一套阅读留白，以便背屏两个阅读面观感一致。
9. 作为机主，我希望长文超出一屏时截断并上下翻页，以便随时读到全文。
10. 作为机主，我希望充电绿水位、呼吸光晕等纯视觉照旧铺满含相机带，以便「大气」不因文字避让而回退。
11. 作为机主，我希望文字避让后每行仍有约 9 字以上的可读宽度，以便翻页不至于太累。
12. 作为机主，我希望防烧屏漂移的任何时刻文字仍不进带，以便漂移不会把字漂回相机后面。
13. 作为机主，我希望应用名解析失败时标题照常显示，以便信息不因采集失败而丢失。
14. 作为验收人，我希望实机截图能量出文字落位坐标，以便「避没避」有客观判据。
15. 作为验收人，我接受「截图判不了物理遮挡」的口径，希望验收记录写明带内遮挡以布局坐标＋肉眼为准，以便不被截图假象骗过。
16. 作为机主，我希望能用一条新通知在实机复验标题省略，以便确认修复真的装进了手机。
17. 作为维护者，我希望避让规则是纯函数、换机型只换几何输入，以便不硬编码机型数字。
18. 作为维护者，我希望「相机带」进领域词条，以便后续 spec 不再各写各的名字。

## Implementation Decisions

- **信息与视觉分界**：承载信息的可读文字避让相机带；纯视觉背景层不避——spec 0009「卡片铺满整个背屏（含相机带）」只授权视觉，不授权文字（此前文字被同口径铺进去属排版盲区，非定案）。
- **文字水平留白规则（:rear 几何纯函数；票 #97 修订）**：左缘 = 静态布局框左界（cutout 收缩＋漂移余量）与内容设计留白两者取 max（cutout 在左/在右对称成立，原判例不变）；右缘 = max(8px 屏缘视觉地板、右侧 cutout 避让、圆角弧区外扩量)——文字垂直位置（含漂移极限位）进弧区时右缘自动外扩，构造性保证不与圆角不可用区相交。渲染层（Detail 卡片、Agent Mirror 层）走同一纯函数照单执行，纵向留白不动。
- **统一阅读留白令牌**：readingGutter（53dp，本机 ≈150px）作两处阅读面的**左缘**设计地板（本机左缘由相机带几何抬到 304，地板在带外几何时才起作用）；Agent Mirror 原「短边 8%」留白档退役。**票 #97 修订**：右留空 105→150 的档位链到此为止，右距改 8px 视觉值排满、文字垂直位置进圆角弧区时右距自动外扩，文字宽 450→592。
- **标题显示口径（:core 纯函数）**：标题 trim 后与应用名忽略大小写相等、且正文非空 → 省略标题行；正文空 → 保留；应用名解析不到（null）→ 保留。
- **应用名采集走 Android 层**：包可见性沿设置页既有口径（launcher 意图查询＋显式 shell 包），不申请全量查询权限；core 只消费结果、不做平台调用。
- **Detail 卡底改纯黑**：复用整屏背景色令牌；深灰卡面令牌删除。
- **快照语义不变**：Detail 仍显示打开那一刻的最新一条通知；再点按收起、清除自动收起等既有行为不动。
- **领域词条**：CONTEXT.md 立 Camera Band（相机带）——定义＋「截屏仍截得到带内像素，判避没避不能只看截图」；Detail View 条目同步为「底色不避、文字让开、标题同应用名时省略」。
- **验收归档**：沿 poc-logs 惯例（session.md＋截图＋erratum）；背屏截屏必须用 SurfaceFlinger display id。

## Testing Decisions

- 好测试只断言外部行为：输入 → 输出（规则结果、几何不变量、像素坐标），不断内部实现。
- **:core 纯函数接缝**（先例 DashboardCoreTest 等中文判例单测）：标题口径五例——同值省略、联系人/群名显示、正文空保留、应用名 null 保留、trim/大小写/包含关系不误判。
- **:rear 几何纯函数接缝**（先例 DisplaySafeAreaTest：本机实测数字直接进断言）：文字横跨不变量——本机左缘 304 档（相机带避让不变）、右距 8px 排满档（**票 #97 起；原「304/150 档」作废**）、圆角弧区用例（上缘进弧区外扩到 51、满高外扩到 97、弧区外不外扩、圆角 0 不外扩、文字矩形在漂移极限位不与角部不可用区相交）、cutout 在右对称成立、左缘设计留白地板、任意几何下右留白 ≥8px 且不越窗。
- **实机截图像素判读**（先例：#76 验收 measure 判读、本轮归档）：screencap 取帧后量文字墨迹起始 x ≥ 304、卡底 RGB (0,0,0)、右缘距屏缘 8px（**票 #97 判据；原「右留空 ≥150」作废**）；证据与 erratum 归档 poc-logs。
- 正案（标题≠应用名）实拍因主屏休眠期截到冻结帧未取到，由纯函数五例覆盖；机主亮屏肉眼复验作为验收备注而非阻塞项。

## Out of Scope

- Icon Set 图标弥散光晕轻微外溢带区——纯视觉软效果，允许被挡。
- 充电电量数字位置——右下锚定、与带区几何不相交，spec 0009/#76 已定案。
- Agent Mirror 的历史翻页、打码档——spec 0010 既有边界。
- 背屏 AOD/Takeover 与主屏休眠期 screencap 冻结帧的环境问题——erratum 在案，不属本 spec 修复面。
- 标题的智能改写/包含匹配——只做「与应用名同值即省略」，不做更复杂判断。
- 主屏安全区——走平台 insets，与背屏相机带是两个对象。
