# Spec 0026：Agent 真流式与全信息镜像

状态：已与机主 grill 收口（2026-10-04，Q1–Q21，frontier 空，末轮“确认”）；实施切片已落地，剩余边界见实施回填。
Issue：#301。
术语沿用 `CONTEXT.md` 的 Agent Mirror、PC 桥、Prompt Bubble、Session Lock、Remote Approval、Agent Alert、Mirror Text Size。
本 spec 取代 spec 0017 中“工具调用/工具结果/思考过程不上屏”和“Codex 只能消息级、不做二期攻坚”的旧口径；
不改变 Detail View、通知页、Remote Approval 核心边界。

## Problem Statement

现有镜像已经能把部分来源的新增内容送进背屏，但仍有三个产品缺口：

1. **到达不够真**：Codex 外部会话要等一整条回答落盘；长时间任务在背屏上看起来像静止。
2. **信息不够全**：工具调用、命令输出、文件变化、错误、耗时和思考过程不在背屏或完整记录中。
3. **恢复与留存不够明确**：高信息量流式输出需要“不丢、不重、不跳”的续接语义，并且不能把几千行日志直接压在正文上。

机主目标是：背屏像电脑端一样持续看到会话正在发生什么；需要原文时能查全，不需要原文时不被日志淹没。

## Product Scope

### 信息分类

| 类别 | 背屏主流 | 完整记录 | 备注 |
| --- | --- | --- | --- |
| 机主提问 | 显示 | 完整保留 | Prompt Bubble 规则继续有效 |
| 正式回答 | 重点显示 | 完整保留 | 原有正文格式继续有效 |
| 模型思考过程 | 显示 | 完整保留 | 低强调样式，不冒充正式回答 |
| 工具/动作摘要 | 显示 | 完整保留 | 如“正在读文件”“想执行命令” |
| 命令输出 | 结果摘要 | 原文可查 | 长输出不铺满主流 |
| 文件读取、修改、创建、删除 | 结果摘要 | 文件内容/差异可查 | 背屏不强制重排 |
| 错误与失败原因 | 显示 | 完整保留 | 包括工具失败与会话级错误 |
| 等待确认与批准结果 | 显示 | 完整保留 | 只沿用现有窄写批准 |
| 耗时、用量、花费 | 详情 | 完整保留 | 不挤占主阅读流 |
| 系统注入、内部提示 | 隐藏 | 隐藏 | 结构明确的注入封装仍过滤 |

“全信息”指来源通过官方接口、会话文件、钩子或现有协议可观测的信息，不承诺模型内部不可观测状态。

### 隐私与安全红线

2026-10-04 机主拍板：**完全原样，不做任何隐藏或打码**。密码、密钥、源代码、文件路径、命令输出等即使出现在回答、思考或工具输出中，也原样进入可见记录。项目不在本 spec 增加隐私模式或自动打码层；实施时不得把这一风险误写成已消除。

### 流式体验

- 正常网络：新内容目标 1 秒内可见。
- 偶发波动：允许 2 秒延迟。
- 超过仍无更新：显示“接收暂停”或明确降速，不得静默停住。
- 各来源允许节奏不同，但都必须提供“增量到达”，不能继续整条等待。
- 思考过程、工具活动、正式回答按真实时间顺序追加。
- 已显示片段不静默改写、不重复、不跳段；来源只提供替换文本时按稳定条目 ID 合并。

### 来源范围

- ZCode：连续增量。
- Claude Code/Cowork：按可观测的新完成行或批次连续到达，不承诺词级。
- DeepSeek Harness：连续增量。
- Codex：电脑端发起和手机 Remote Codex Conversation 发起的会话体验一致，均追求连续增量。
- Claude Desktop Chat 标签：继续不镜像；Code/Cowork 仍是可镜像范围。

Codex 特殊成本：现有 rollout 观察只能可靠拿到整条回答。要满足“电脑发起也真流式”，必须让被镜像的 Codex 会话进入桥可观察的实时通道；这可能改变首次 PC 配置或 Codex 启动路径。不得静默把电脑发起的会话降级为整条到达，除非机主另行明确接受。

## User Stories

1. 作为机主，我想在回答生成过程中持续看到新片段，以便知道它没有卡住。
2. 作为机主，我想看到思考过程但不把它误认成正式回答，以便理解工作进展。
3. 作为机主，我想在背屏看到工具正在做什么和是否成功，以便判断任务风险。
4. 作为机主，我想点开工具摘要查看命令原文、文件内容和差异，以便需要时查全。
5. 作为机主，我想在断网后恢复时补齐遗漏内容，以便不漏掉关键结果。
6. 作为机主，我想让电脑发起和手机发起的 Codex 会话有一致速度，以便不把差异当成故障。
7. 作为机主，我想在整轮正式回答完成后才收到“没阅”，以便不被中途思考反复打扰。
8. 作为机主，我想切回会话时直接回到最近正式回答，以便继续阅读上下文。
9. 作为机主，我想看到接收暂停、已接续和到期清理痕迹，以便区分产品故障、网络中断和数据清理。
10. 作为机主，我接受完整内容不打码所带来的隐私风险，以便获得全信息。

## Implementation Decisions

### 一、来源侧事件归一

桥适配器输出统一结构化“内容条目”，不再只输出 `userText` / `assistantText` / `assistantDelta` 三类字符串：

```text
entry {
  entryId, sessionId, source, kind,
  role?, text?, detail?, summary?,
  ts, status?, open?, complete?,
  toolName?, command?, path?, outputRef?
}
```

`kind` 至少区分：`prompt`、`answer`、`thinking`、`tool`、`tool_result`、`error`、`approval`、`usage`、`system_hidden`。`system_hidden` 只能在桥内用于过滤，不得下发。

- `prompt`：机主真实提问。
- `answer`：正式回答正文。
- `thinking`：模型思考过程。
- `tool`：动作摘要，可带工具名、命令摘要、路径摘要。
- `tool_result`：结果摘要；大文本放 `detail` 或按详情引用读取。
- `error`：工具失败、会话失败、传输失败。
- `approval`：等待确认和批准结果。
- `usage`：耗时、token/用量/花费等详情。

来源适配器只负责“把来源事实翻译成条目”，不在来源侧做 UI 取舍。结构明确的注入记录在进入条目前过滤；无法确认的普通文本不得误杀。

#### Codex

- 手机远程发起的 Codex：优先消费官方实时事件中的用户、思考、工具、回答、批准和完成事件。
- 电脑发起的 Codex：接入同一实时观察面；rollout 只作为历史补齐和断线兜底。
- 若实时面只能提供文本增量，先保留 `thinking`/`answer` 条目和时间顺序；工具细节可在完成事件到达时补 `detail`。
- 外部进程无法实时观察时，不伪造逐字效果；必须由实施者在日志和验收报告中记录能力边界。

#### Claude / ZCode / DSH

- Claude `MessageDisplay` 批次映射为同一 `answer` 条目的增量；`Stop` 只收口，不重发整段。
- ZCode `row.delta` 映射为 `answer` 或 `thinking` 增量。
- DSH `assistant-delta` 映射为 `answer` 增量，工具和批准按现有事件补 `tool`/`approval`。
- 三者产生的工具、错误、结果若来源只给摘要，就保留摘要并在 `detail` 可查范围内存原文。

### 二、桥侧传输与续接

桥把内容条目按“增量事件”下发，不再每次把整个问答数组当正文重发。每个事件至少带：

```text
eventId, sessionId, entryId, op, payload, occurredAt
op: append | patch | complete | reset
```

- `append`：追加新条目或新片段。
- `patch`：补工具结果、错误、耗时或状态。
- `complete`：收口开放条目。
- `reset`：会话重建/历史对齐；必须带可解释原因。

现有 `/events?since=<cursor>` 长轮询继续作为实时通道，游标必须单调；客户端按 `eventId` 幂等合并。`GET /history?sessionId=` 扩展为结构化条目分页，供完整记录和断线补齐。

桥应保留两层：

1. **实时事件层**：供增量、唤醒和游标续接。
2. **会话完整记录层**：供当前会话完整历史、工具原文和断点对齐。

事件环溢出或桥重启时，不能让手机猜内容：返回 `reset` 或快照对齐信息，让手机从可信边界重新合并。桥日志不得因为“全信息”而把凭据、密钥原文重复写入日志；用户可见记录和诊断日志是两个不同面。

### 三、手机端合并与完整记录

手机端新增结构化流存储，负责：

- 按 `sessionId + entryId + fragmentSeq` 幂等追加。
- 将 `open` 条目显示为正在增长，`complete` 后收口。
- 在断线期间保留已收片段；恢复后先补齐缺口，再恢复实时。
- 同一回合中优先维护最近正式回答锚点，供切回定位。
- 将 `detail` 原文保存在会话完整记录，不让超长原文无限挤占主画面。

背屏主流只显示可读摘要；点击 `thinking`、`tool`、`tool_result`、`error` 等摘要块，展开对应 `detail`。另有“本轮完整记录”入口，可查看该轮全部条目和原文。

### 四、呈现规则

- `thinking` 与 `answer` 同时间流，但以低强调灰字/低对比度显示；不得使用正式回答相同的视觉权重。
- `tool` 只显示一句动作摘要；命令原文、文件内容、差异进入展开详情。
- `error` 显示失败对象与可行动原因；长堆栈只在详情。
- `approval` 只复用现有同意/拒绝/选择窄写入口，不引入自由文字或任意按键。
- `usage` 默认收在详情，不把 token/费用作为主正文。
- `system_hidden` 不上屏；无法确认的文本按可见条目保留。
- Detail View、通知 Icon Set、充电背景层、内容页切换和标题渐隐规则不变。

### 五、切回、未读与多会话

- 切回某会话：存在正式回答时定位到最近一条正式回答；不存在正式回答时定位到最新内容。
- 正在实时跟随的会话继续实时跟随；回看锁位规则不变。
- 生成中的思考、工具活动不产生“没阅”。
- 整轮正式回答完成后产生蓝色“没阅”；打开正文后标已阅。
- 自动档沿最近活动会话仲裁；手动 Session Lock 不被其他会话抢占。
- 不把多个会话混成一条流；其他会话只通过 Agent Alert 或状态标识提醒。
- Agent 流不抢通知页；Waiting-for-Approval 继续按既有规则插队。

### 六、历史留存与清理

- 当前会话：完整历史。
- 其他会话：保留 30 天。
- 其他历史总容量上限：约 500 MB。
- 当前会话不因普通期限清理。
- 到期或容量清理静默执行，但完整记录页显示“部分内容已到期清理”。
- 清理不得删除仍在进行中的开放条目；先保留最近活动会话。

### 七、资源与刷新

- 传输层追求即时，渲染层允许合批。
- 连续输出时保持视觉连续，不为每个字反复重绘；既有刷新上限继续作为渲染护栏。
- 充电时允许更积极刷新；非充电、后台或发热时降低刷新压力。
- 降级只能降低刷新频率或合并片段，不能退化成整条等待。

## Testing Decisions

### 纯逻辑判例

1. 条目归一：来源事件 → `prompt/answer/thinking/tool/tool_result/error/approval/usage`。
2. Codex 实时与 rollout 兜底：同一会话不重复、不跳段，外部不可观察时有明确能力标记。
3. 增量合并：`append/patch/complete/reset`、稳定 ID、乱序重放、重复事件幂等。
4. 断线续接：中断期间片段补齐、事件环溢出后的快照/重置、无静默丢内容。
5. 完整记录：详情原文分页、展开数据不污染主流、超长输出不撑爆内存模型。
6. 未读：思考/工具不触发，正式回答完成触发，打开正文标已阅。
7. 切回定位：有正式回答到最近正式回答；无正式回答到最新内容。
8. 清理：30 天、500 MB、当前会话保护和清理痕迹。

### 桥侧判例

- 四源输入均能产出结构化条目。
- Codex 电脑发起和手机发起使用同一出口形状。
- Claude/ZCode/DSH 的增量不被整段重发覆盖。
- `system_hidden` 不下发，普通相似文本不误杀。
- 游标、历史分页和事件环溢出行为可重复验证。

### 手机侧判例

- 条目合并、开放条目收口、断线补齐、切回锚点。
- 主流摘要与详情原文分离。
- 思考低强调不改变正式回答排版。
- 未读、Session Lock、Waiting-for-Approval、通知页和 Detail View 零回退。

### 实机验收

1. 正常网络：1 秒级片段可见；偶发延迟不超过 2 秒。
2. 人为断网/恢复：显示暂停与已接续，内容不丢不重。
3. 四源各跑一轮：ZCode、Claude Code/Cowork、DSH、Codex。
4. Codex 电脑发起与手机发起对照。
5. 思考、工具、错误、批准、用量、完整记录逐项目检。
6. 超长命令输出：主流不被冲走，详情可查原文。
7. 切回定位、未读、自动仲裁和手动锁对照。
8. 通知页、Detail View、充电背景层回归。
9. 30 天/500 MB 清理用隔离测试数据验证并留痕。

## Out of Scope

- 模型内部不可观测状态、来源软件未暴露的私有数据。
- Claude Desktop Chat 标签镜像。
- 任意电脑控制、自由文字审批、任意按键。
- 跨会话搜索、跨会话翻页、语音、图片、成本预测。
- 全局系统无障碍字体缩放。
- 为隐私风险提供打码或隐私模式（本机主已明确选择完全原样）。
- Detail View 的版式、字号和通知行为改变。

## Acceptance

1. 四类可镜像来源提供增量到达，不再整条等待。
2. Codex 两种发起路径一致；能力不足处有明确标记而非静默降级。
3. 思考、工具摘要、错误、批准、用量进入约定位置。
4. 完整记录可查命令原文、文件内容和差异。
5. 断线恢复不丢、不重、不跳，并显示暂停/已接续。
6. 1 秒目标、2 秒波动阈值和渲染合批符合产品口径。
7. 切回定位、未读、Session Lock、Waiting-for-Approval、内容页行为不回退。
8. 30 天/500 MB 清理有可见痕迹，当前会话完整历史受保护。
9. `gradlew test` 与桥侧 Node 测试保持全绿；实机证据归档。
