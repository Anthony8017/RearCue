# Spec 0027：Codex Pending User Question（待答问题）

2026-10-06 修订设计见 [Spec 0031](0031-rear-question-choice.md)：用户要求不自动打开并支持背屏选项作答。修订仍在 grilling，本文件保留已部署首期行为与验收记录。

状态：已收口、已实现，2026-10-05 本地及独立实机验收通过；联合装机由“语音播报滚动”协调。Q1–Q5 按推荐确认；Q6 经二次调查仍无稳定低成本入口，按机主“再看一下识别跳过的实现难度如何，不行的话按推荐”授权采用推荐边界。
日期：2026-10-04。术语采用 CONTEXT.md 的 Pending User Question、Waiting-for-Approval、Session Picker、Status Glow、Agent Alert 与 Remote Approval。

## Problem Statement

Codex Desktop 弹出问题时，RearCue 未识别 Pending User Question，背屏在列表时无法提示机主。
异步提问后 Codex 可以继续工作，因此待答问题不能直接等同于“停下等待批准”，也不能被后续输出清除。

## 已定范围

1. **Q1：自动打开问题。** 背屏从列表或当前页面打开该会话的问题正文，显示绿色等待提示，并按现有 Agent Alert 设置发送手机通知。
2. **Q2：首期只提醒、电脑端回答。** 在电脑回答后自动解除对应问题提醒；本次不增加手机点选答案，不显示无效的“同意/拒绝”批准按钮。
3. **Q3：仍在工作也立即提示。** 异步提问不必等 Codex 停下；只要有新的待答问题就自动打开并提示。
4. **Q4：未答可以切走。** 机主可以手动切回列表或通知页；未答绿点保留，同一个问题不反复抢屏。
5. **Q5：答完回原页面。** 恢复提醒前的页面，原先在 Session Picker 就恢复列表；提醒期间机主手动切页，则保持机主最新选择。

## 交互与恢复

- 待答问题与 Waiting-for-Approval 分开：问题可与工作中并存，可手动切走；批准等待继续沿现有不可切走规则。
- 问题正文可读，答案选项可展示为问题内容；本期不将它们渲染成可提交的批准按钮。
- 打开问题时保存原内容页、列表是否打开与当前会话选择；自动提示不改写机主的持久 Session Lock。
- 正在回看问题时，该会话新的思考或工具输出不让问题消失；在电脑回答对应问题后解除，不以任意输出替代答复。
- 同一个问题的重复记录和流式更新不制造新提醒；多题只解除已有答复的题目，其余待答题保留。
- 提醒沿现有总开关与震动设置；问题处理后对应旧提醒撤回，避免“已答仍提示”的残留。

## 验收

1. 从列表收到新问题后打开正确会话与问题正文，亮绿灯并按设置提醒。
2. Codex 继续工作、工具返回“已接受”、收到与问题无关的用户消息，都不会误解除未答题。
3. 未答可切回原列表或通知页；后续同题记录不会再次抢屏；列表保留绿色待答标识。
4. 电脑答复按调用与题号解除：部分回答不清空其他题；全部处理后回原页面及原列表，手动切页后不再自动恢复覆盖。
5. 问题不是批准：主屏、背屏与通知不显示无效的同意/拒绝或手机提交答案入口；既有批准链回归正常。
6. 桥重启、手机重连恢复待答事实；归档会话不出现、不提醒、不插队。
7. 本轮完成、停止或开始新一轮后解除该轮异步问题提示，历史问题正文保留；不能把它误记为“机主已回答”。
8. 电脑端单独跳过的即时同步按 Q6 最终选择验收，不假装已经取得可靠跳过信号。

## 验证落位

- 桥侧适配器与真实形状 fixture：创建、立即接受回执、普通工作增量、逐题回答、重复事件与冷启动。
- 桥事件及手机归一：问题信息与任务状态可同时存在，快照及增量一致，归档边界保持。
- DashboardCore：首次插队、原列表恢复、未答允许切走、手动选择优先、同题不再插队、多会话与批准优先规则。
- 提醒/批准判定：问题只提醒、答完清旧提醒、真正批准保持三入口。
- 背屏实机：列表→问题→切走→电脑回答，目测绿点/光带及原列表恢复；真实桥部署重启须遵守 AGENTS.md 常驻桥退出规则。

## 已核事实与实施约束

事实来源：[调研记录](../research/codex-user-input-waiting.md)。

- 本机异步提问存在创建记录和逐题回答记录；工具返回“已接受”只代表已展示，不是机主答复。
- 问题按创建调用及题号关联；普通用户消息、继续工作、工具输出不代表所有问题已答。
- 问题与任务运行状态分别追踪，避免绿色提示覆盖、清空或误报实际工作状态。
- 桥重启须重建未答问题，不能沿用只读取旧文件末尾的方式而宣称已恢复。
- 归档会话仍遵守现有来源在册规则，不因待答问题重新出现。
- 普通 Desktop 的手机答题通道未验证；现有桥内 app-server 批准通道不能冒充 Desktop 问题回写。
- 同步提问没有本机实测样本，本票以当前 Desktop 已实测的异步提问形态为验收入口。
- 当前 Desktop 源码已核实：异步提醒只在对应当前回合仍进行中、未提交且未跳过时有效；回合完成、中断或换回合会结束该轮提示。这个边界按来源事实解除，不记作已答，也不删除历史正文。
- 单独点击跳过只改 Desktop 内部显示状态，没有已验证的日志信号；不能声称已支持跳过的即时同步，也不设时间猜测已答。

## 已定边界：Q6

电脑端点“跳过”后，背屏可能要等该轮结束才撤掉绿色提示；本轮结束、停止或新一轮开始会自动解除，回答则立即解除。第二轮调查仍未找到稳定合理成本的跳过观测入口，按机主条件授权采用此推荐边界，不修改 Codex 程序，不把关闭窗口或系统通知消失猜成跳过。

## 验收结果与合入提示

- JVM：agent 149、core 260、app 147、rear debug 251，全部通过；APK 构建通过。
- 桥：适配器旧判例 16、题目生命周期 4、问答流 22、统一桥协议 47，相关判例均通过。
- [实机记录](../poc-logs/20261005-codex-pending-questions/README.md)：问题与绿灯、工作增量保题、答完回原列表、未答手动切走、同题不抢屏、回答不覆盖手动通知页。
- 重连先收到当前快照时，以桥的单调 `id`（`bridgeRevision`）挡住较旧活动，避免旧题复活；手机侧 `updatedAt` 仍沿既有到达时间口径，仲裁不受 PC 时钟偏差影响。
- 联合版本需保留真实批准的视觉优先与不可切走规则；待答题保持独立事实、可切走及回答后恢复规则。待答题首期不当作批准，不改真实任务运行状态。
- 因同机并行装机会覆盖已安装版本，机主授权统一协调后，本会话停止进一步装机、输入和录屏；验收 fixture 已从桥在册集移除。
