# Spec 0028：本轮过程折叠与空闲没阅会话入场定位

状态：Q1–Q9 已确认并实施；验证与装机记录见文末。
日期：2026-10-05。
术语采用 CONTEXT.md 的 Agent Mirror、Prompt Bubble、Turn Process、Session Entry Anchor、Session Picker 与 Session Read State。

2026-10-07 展示修订（已实现，实机验证待完成）：机主最终确认保留本轮过程折叠；展开后在正文原位置读全，取消「完整记录」入口，不再增加第二层折叠。此规则取代下文历史描述中的独立完整记录入口与原文仅在详情页可读的约定，其他开合及入场规则继续有效；实现与验证边界见 spec 0026 的展示修订。

## 问题与目标

任务结束后，思考和工具记录仍挤在阅读流中；从列表点入空闲没阅会话时，现有换会话逻辑会恢复实时跟随并滚到底，无法从机主最后发出的消息开始读。

目标：只改背屏 Agent Mirror。每轮过程可折叠；点入空闲没阅会话时，把机主最后发出的消息放到顶部可读位置，并保持阅读位置。

## 已定规则

### 本轮过程

- 每个回合的思考、工具调用和工具结果归为一个「过程」折叠组；不将整个会话的多轮过程合成一组。
- 进行中的新回合默认展开，继续显示实时过程；正常完成、主动停止或失败后默认收起。等待批准、存在待答问题或短暂没有输出不算结束。
- 点过程组可手动展开或收起。原有条目详情和完整记录仍可查看，折叠只改变呈现，不删除原文。
- 机主消息、正式回答、错误原因、批准及待答问题留在折叠组外；错误不可随过程一起藏起。Notice Line 和用量详情沿用既有规则。
- 同一轮内的原始记录及其时间顺序完整保留；归组不能吞掉、重复或冒充正式回答。
- 机主正在历史回看或查看过程详情时，回合结束不自动改变当前展开状态，也不改变当前可见位置；退出这次回看后，未被手动设置的过程组再按结束后的默认收起处理。
- 手动展开/收起是该回合的显式选择，优先于自动收起；再次进入同一会话时保留。它不决定后续新回合的初始状态。

### 空闲没阅会话的入场锚点

- 仅由机主在背屏 Session Picker 点入「空闲没阅」会话时触发；选中前判断该状态。
- 定位对象是会话内**最近一条机主实际发送的消息**，即 Prompt Bubble，包含来源已识别的问卷作答；不是 AI 的最后答复。系统注入上下文不参与定位。
- 入场时该消息的首行对齐**标题及渐隐带下方、不受遮挡的正文可读区上沿**。首行完整可读，标题、状态标识与列表入口继续常驻。
- 即使末轮内容不足一屏，也按这个锚点排列，不把短消息重新居中；必要时保留末尾空白，使短内容也能定位。
- 同一会话重新从列表点入且仍为空闲没阅时，也重新应用该锚点，不沿用之前的滚底或回看位置；过程组的手动展开状态仍保留。
- 锚点应用后进入固定阅读状态；历史补齐、条目更新、新内容到达及过程组默认收起，均不得把页面推回底部或移走当前可见内容。
- 机主可继续手动滚动；点既有 ↓ 按钮后恢复实时跟随。仅在当前会话自然完成，不触发一次新的入场定位。
- 没有可识别的机主消息时，本规则无锚点可用，沿用现有入场行为，不伪造提问泡。锚点尚在补齐时，补齐后定位一次；机主已开始手动阅读则放弃迟到的自动定位，避免打断阅读。

### 既有规则与范围

- 适用于背屏现有可镜像来源；不新增手机主屏正文页。
- 已阅触发沿用当前 CONTEXT.md：点列表、标题或仅自动呈现不算已阅，点正文按现有规则发回执。折叠、定位本身不额外产生已阅。
- 已阅、工作中、等待、出错等其他入场情形，沿用现有规则；错误会话虽可收起过程，不因此进入本次「空闲没阅」定位路径。
- Session Lock、列表排序、Agent Alert、正文格式、字号、角部避让及通知 Detail View 不变。
- Waiting-for-Approval、Pending User Question 与 Voice Broadcast Follow 沿用各自优先级和人工阅读暂停规则；不能把普通新输出当成插队理由。

## 与既有文档的关系

- **局部取代 spec 0026 的「切回最近正式回答」目标**：只有本次明确的空闲没阅列表入场，改为机主最后发送的消息；其他入场不扩展承诺。
- **增加 spec 0026 的按轮过程折叠**：条目详情、完整记录与原文留存继续有效，完成收起与人工展开优先采用本 spec。
- **局部取代 spec 0025 的短内容居中**：Session Entry Anchor 生效时按顶部可读位置对齐；普通短内容继续居中，顶部标题覆写与渐隐效果保留。
- Session Read State 按现行 CONTEXT.md 与 ADR 0018 的后续修订执行；本次不恢复旧的「看见正文即已阅」口径。

## 实施前核实的边界

- `AgentReadingText` 已分别呈现机主消息、思考、工具、结果与错误；点击有 detail 的条目可开详情，目前没有按轮折叠组。
- `RearDashboardActivity` 当前对同会话保留回看、换会话恢复跟随；`AgentMirrorView` 在跟随态遇到内容更新会滚到底。实施须同时处理入场与后续更新，不能只改首次滚动。
- `AgentReadingText` 的短内容目前居中，顶部正文可能进入标题渐隐层；实施须验证短消息也能停到首行可读位置。
- Codex 正常完成和主动停止均进入 idle，但具有不同的结束事实；不得只凭 idle 推断一次正常完成，也不能把 Waiting-for-Approval 当作结束。
- 主屏目前只有会话列表/锁定设置及 Codex 新建、追问面，本次不扩展该表面。

## 验收条件

1. 每轮只有一个逻辑过程组；进行中默认展开，正常完成、停止和失败后默认收起，下一轮默认展开。
2. 思考、工具及结果可展开，并仍能查看原文；机主消息、正式回答、错误与待处理事项保持可见。
3. 回看或查过程详情时恰好结束，当前状态和可见内容不跳；手动展开再次进入同会话仍保留，自动收起不覆盖人工选择。
4. 点入空闲没阅会话后，机主最后一条实际消息在顶部可读位置；不得定位到 AI 答复、旧提问或注入上下文。
5. 短消息、长消息、长回答、问卷作答及多回合会话都能正确定位；短内容不重新居中，首行不被标题或渐隐带遮住。
6. 同一会话重新点入、换会话点入及历史稍后补齐均符合入场规则；无机主消息时沿用既有行为。
7. 入场后的历史补齐、条目更新、普通新输出与过程折叠不将页面推到底；手动滚动保持可用，点 ↓ 后恢复跟随。
8. 只在从列表点入符合条件的会话时应用锚点；当前会话自然结束不重新跳到机主消息。
9. 列表/标题/自动定位不新增已阅回执；正文已阅、列表排序和跨端事实按既有规则回归。
10. 真正批准、待答问题、播报跟随暂停、会话锁定、四源镜像和通知详情保持既有边界；手机主屏不出现新增正文页。

验证重点：回合归组及折叠优先级、入场资格与锚点选择、迟到历史和新输出不滚底的行为判例；背屏实机目检顶部首行、短内容定位、折叠开合及人工阅读稳定性。

## 实施回填（2026-10-05）

- 桥记录新增可选的 `roundId` / `roundComplete`，真实回合开始与结束统一归组；作答不另开轮，停止/失败也收口。重复开始、迟到旧完成及相同文字的新回合有独立判例。
- 手机兼容旧桥：有回合标识优先按来源回合分组，旧记录按机主提问划分；展示投影不修改原始历史。每轮只有一个过程开合入口，正式回答与错误仍为独立条目，详情与完整记录保留。
- 人工开合按会话及回合保存在本地，重入和 App 重启保持；回看与详情期间冻结内容及结束默认状态，恢复跟随后接上后台更新。

- 固定阅读不因触底、布局钳底或新内容恢复跟随；点 ↓ 恢复。程序化定位和跟随滚动不被误判为人工回看，不新增已阅回执。
