# Spec 0008：背屏视觉升级（纯图标常态 + Notification Highlight + Detail View + 充电绿色比例）

状态：已与机主 grill 收口（2026-09-27），frontier 空；三轮决策全部按推荐或机主直给定案。
本 spec 显式反转 spec 0007 的两处产品决策（横幅撤下、闪电改绿色比例，见 Further Notes）。

## Problem Statement

Dashboard 目前是「黑底 + 时间 + 图标集」，视觉平淡且无事件反馈：新通知到达只有图标静默变化，远处一眼感知不到「来消息了」；想知道消息内容必须拿起手机翻主屏；充电只有一枚小闪电图标，电量比例不可见。机主要求贴贴小米原生背屏的设计语言（黑底为纲、光效克制）做整体美化，并补三件事：通知到达的瞬态强调、点开图标看通知全文、充电时整屏电量图示。

## Solution

Dashboard 重构为「一常态 + 两瞬态」，全部仍嵌在既有 Dashboard 内、不新增背屏 Activity：

- **常态＝纯 Icon Set**：不显示时间（原生背屏已有时钟），无横幅——spec 0007 的 Notification Feed 从背屏撤下，内容展示职责移交 Detail View。
- **Notification Highlight（通知高亮）**：新通知到达（含同 key 内容更新）⇒ 整屏呼吸约 3 秒 + 新到 App 的图标以统一暖白强调色高亮；30 秒冷却防群聊刷屏（冷却内不重复呼吸、新图标照常入高亮）；熄灭时机＝该 App 的 Detail View 被点开看过即熄，未看则其通知被清除时熄。
- **Detail View（通知详情）**：点按 Icon Set 中某枚图标 → 图标放大淡出、卡片弹性展开（过程动效是产品要求），显示该 App **最新一条**通知全文（标题+内容）；再点按收起；所示通知被清除自动收起；无隐私档（点开即本人主动）、无限时、不做多条堆叠。
- **充电＝整屏绿色电量比例**：背景自底部按当前电量比例被绿色渐变光填充（上缘亮边微光），白色大号数字显示电量，Icon Set 带白描边保持可见；替代 spec 0007 的 2D 闪电。触发/退出与总开关语义不变（插电独立触发、不受两道门、拔电∧Icon Set 空即退、应用内总开关默认开）。

设计稿四张（ChatGPT 生成、机主已过目）：`docs/mockups/0008-dashboard-visual/chatgpt/`（常态 / 高亮瞬间 / 点开全文 / 充电 68% 示意）。

## User Stories

1. 作为机主，我希望背屏常态只显示 Icon Set（无时间、无横幅），以便背屏成为纯粹的通知指示面。
2. 作为机主，我希望新通知到达时整屏呼吸约 3 秒，以便远处一眼感知「来消息了」。
3. 作为机主，我希望新到通知的 App 图标以暖白高亮区分出来，以便看清是谁在等我。
4. 作为机主，我希望群聊刷屏时 30 秒内只呼吸一次（新图标照常加入高亮），以便背屏不持续闪动惹人烦。
5. 作为机主，我希望点开某 App 的图标看过全文后它的图标高亮即熄，以便高亮承载「未看」语义。
6. 作为机主，我希望没看过的通知在其被清除后图标高亮自动熄灭，以便背屏不留过期指示。
7. 作为机主，我希望同一条通知内容更新时也触发一次呼吸（受同一冷却约束），以便「横幅刷新」式的变化仍有感知。
8. 作为机主，我希望点按图标后图标放大淡出、通知卡片弹性展开显示全文，以便点开过程精美流畅。
9. 作为机主，我希望 Detail View 显示该 App 最新一条通知的标题与全文，以便不翻手机知道消息内容。
10. 作为机主，我希望再点按一下收起 Detail View，以便看完即回纯图标常态。
11. 作为机主，我希望 Detail View 所示通知被清除时自动收起，以便不显示已不存在的内容。
12. 作为机主，我希望 Detail View 直接显示全文（无隐私遮蔽档），以便点开即读、无第二次操作。
13. 作为机主，我希望充电时整屏背景按电量比例绿色填充并显示大号数字，以便隔着房间看清电量。
14. 作为机主，我希望充电时 Icon Set 带白描边保持可见，以便充电不丢通知指示。
15. 作为机主，我希望无通知时插电也点亮背屏显示电量图示（插电独立触发、不受门控），以便床头随看随见。
16. 作为机主，我希望拔电且 Icon Set 为空时背屏自动交还原生界面，以便充电反馈不残留。
17. 作为机主，我希望充电动效保留应用内总开关（默认开），以便不需要时彻底静默。
18. 作为机主，我希望 Highlight 与 Detail 遵循既有门控（DND 撤下、倒扣不投、手动豁免），以便场景语义与既有行为一致。（**#99/#100 已变更**：DND 撤下已废止；倒扣不投仅姿态开关开启时成立）
19. 作为机主，我希望背屏整体视觉贴原生设计语言（纯黑为底、暖白强调、光效克制），以便看起来是「原生该有的样子」。
20. 作为机主，我希望背屏亮度跟随系统不做特殊提亮，以便夜间不刺眼、无新增设置项。
21. 作为开发者，我希望 Rear Tap 可行性先经真机验证票裁决（票 #7 的原生手势劫持风险），以便 Detail View 不建立在未验证的交互能力上。
22. 作为开发者，我希望 Rear Tap 验证 no-go 时按既定退路收口（背屏纯展示、全文在主屏 App 看、Highlight 熄灭退化为通知清除即熄），以便不可行时产品仍成立。
23. 作为开发者，我希望 Highlight 触发/冷却/熄灭、Detail 打开/收起、充电比例更新全部以事件进 `DashboardCore` 既有 seam，以便全部语义有 JVM 单测。
24. 作为开发者，我希望横幅语义从事件面与设置页干净退役（Privacy Mode、Auto-dismiss 设置项移除），以便无死代码与死设置。
25. 作为开发者，我希望动效渲染（呼吸/展开/填充）不写 JVM 测试、以实机验收链替代，以便测试只测决策不测渲染。
26. 作为开发者，我希望验收轮留痕 poc-logs（沿用 E 系列惯例），场景至少覆盖：高亮触发/冷却/两种熄灭、点开/收起/清除自动收、充电比例与数字随电量变化、拔电退出、门控交叠（DND 中到达不呼吸〔**已废止，见 #99**〕、倒扣不投〔姿态开关开启时成立，见 #100〕）。
27. 作为开发者，我希望 `gradlew test` 既有基线 0 失败不回退。

## Implementation Decisions

- **模块改动**：`:core`（Highlight 状态机〔触发/呼吸窗/冷却窗/按 App 熄灭〕、Detail 打开/收起事件、充电电量数据面、横幅事件面退役）；`:notification`（title/text 已随 spec 0007 挂在 Active Notification 上，无模型改动）；`:rear`（Dashboard UI 重构为纯图标常态、呼吸/展开/填充三组动效、Rear Tap 点击处理）；`:app`（设置页移除 Privacy Mode / Auto-dismiss 两项、保留充电总开关）。
- **Rear Tap 前置**：独立验证票先行（E 系列实验口径）——验证背屏点按能否被 Dashboard 独占接收、不触发 SubScreenCenter 原生手势（票 #7 曾观测上滑触发 `startRecentAnimation` 顶掉 Dashboard）。no-go 退路已定：Detail View 砍掉、全文移主屏 App（另开 spec）、Highlight 熄灭只保留「通知清除即熄」。
- **Highlight 语义**：触发源＝白名单 App 的 Posted 与同 key Updated；呼吸时长约 3 秒；冷却窗 30 秒（呼吸中/冷却中不重复呼吸，新 App 图标照常入高亮）；熄灭＝该 App Detail View 打开（看过即熄）或其全部 Active Notification 清除；强调色统一暖白（对齐全套设计稿的 #F2E9D8 系）；亮度跟随系统，无提亮逻辑，无常驻动画，无应用内开关。
- **Detail View 语义**：数据＝该 App 最新一条 Active Notification 的 title+text（NLS extras 内存读取，沿用 spec 0007 story 15 的隐私边界）；收起＝再点按或所示通知 key 被清除；KeyGuard/锁屏态行为沿自动路径现状，不加特殊处理；无列表、无历史、无横幅遗留。
- **充电语义**：触发/退出/总开关/门控豁免全部沿 spec 0007 原判（charging 来源标签、拔电∧Icon Set 空即退）；显示面改为整屏绿色比例填充 + 白色大数字（电量百分比，BatteryManager 既有数据）+ Icon Set 白描边；闪电动画删除。
- **几何约束**：`DisplaySafeArea` 既有判例照单执行——数字与 Icon Set 落内容安全矩形（本机可用区 608×572、圆角 97、漂移 ±8px 轮驻）；绿色填充为背景层不参与漂移，填充上缘亮边随比例移动时不得遮蔽数字/图标的可读性（实现期按 E15 截图口径复核）。
- **视觉基调**：以设计稿四张为准（黑底、暖白强调、克制光效）；实现期引入 ui-taste 技能做视觉层级审校（`npx skills add https://uizze.sh/`，机主指定参考）。
- **门控复用**：Highlight 与 Detail 属自动路径内容，DND Follow / Posture Gate / 来源标签原样适用，无新增门控（**#99/#100 已变更**：DND Follow 已删、Posture Gate 现为用户开关默认关——「原样适用」只剩来源标签与姿态开关开启态，见 spec 0006 状态注）；Quick Tile Entry 手动投送的手动豁免不变。实现期定案（票 #65，判例钉死）：两道门只绑**投/撤**——呼吸与 Detail 是视图级效果，豁免源（manual/charging）在屏时正放照常呼吸/可点开；重连快照差分补报是重建不是到达，入高亮集但不呼吸（评审 P2 定案）。
- **spec 0005 边界不反转**：单条通知增删/屏蔽仍永不实现——Detail View 只读显示，不提供任何管理对象；未读数/数字角标仍永不实现。〔「未读数/数字角标」半句由 issue #101（2026-09-28）反转：Icon Set 网格档每格 Active Notification 计数角标；「单条管理」仍不反转。〕

## Testing Decisions

- 好测试只测事件→效果。全部新语义进 `DashboardCore` 既有 seam（本轮无新 seam）：Highlight 触发/呼吸窗/冷却窗/两种熄灭、Detail 打开/收起/所示通知清除联动、充电电量数据更新、横幅退役后事件面收敛、与门控交叠（DND 中到达不呼吸且随撤〔**已废止，见 #99**〕、倒扣不投〔姿态开关开启时成立，见 #100〕、手动投的豁免）、charging×manual 交叠既有判例不回退。
- Compose 动效渲染（呼吸曲线、展开过渡、填充渐变）不写 JVM 测试（无决策）；以实机验收链替代（story 26）。
- Prior art：`DashboardCoreTest` 的 Allowlist 三态、门控、manual×charging 判例——同 seam、同风格。
- 基线：`gradlew test` 既有基线 0 失败不回退；验收轮归档 poc-logs。

## Out of Scope

- 多条通知堆叠列表、历史回看、跨 App 轮播详情。
- 未读数/数字角标（永不实现）。〔反转留痕：issue #101（2026-09-28）在 Icon Set 网格档引入每格角标（数字 = Active Notification 条数），判例以 CONTEXT.md「Icon Set」为准。〕
- 主题切换、样式/颜色/动效强度设置项（固定一套精心设计的样式）。
- 常驻动画（时间表盘、待机律动等）。
- 背屏亮度提亮/自适应逻辑。
- 主屏 App 展示通知全文的实施（仅当 Rear Tap 验证 no-go 时作为后续 spec 立项）。
- 充电数字以外的充电信息（功率、充满时间估算、电池温度）。
