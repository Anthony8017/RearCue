# Spec 0034：优先通知与显示优先级

日期：2026-10-13
状态：已实现；JVM 回归与 APK 构建通过，实机验收待完成。

## 已确认行为

- 白名单应用各有「优先通知」开关，默认关闭；移出名单清除此开关，重新添加默认关闭。
- 设置页提供四项拖动排序：待确认、待答问题、优先通知、语音播报。越靠上越先显示，默认顺序如上。应用不逐个排序。设置即时生效，设备本地持久化。
- 仅真实新增通知触发；同 key 内容更新、重连/重启快照、开启开关都不触发。通知内容不新增落盘。
- 不绕过现有姿态门控和投送通道条件。手动退出只结束当前投送，下次真实新通知仍可自动投送。Dashboard 未在背屏时，允许投送则直接显示通知页。
- 跳到现有通知页，不额外自动打开触发通知的详情；现有图标与详情规则继续有效。显示后停留到手动切页，不计时恢复 Agent 页。
- 高排序内容挡住优先通知时，延后到其结束；延后期间触发通知已移除则取消，多条合并一次跳转。已显示后移除通知不会恢复旧 Agent 页，但既有退屏条件继续适用。
- 手动切页、选择会话取消已触发的通知跳转；后续新的优先通知仍能再触发。手动退出取消本次通知跳转。
- 排序完全生效：优先通知可排在待确认之上；问题或语音也可排在待确认之上。仅调整显示顺序，不更改批准状态、答案、Session Lock 或语音播放。
- Codex 待答问题沿用 spec 0031 的被动提示，不因排序设置新增自动打开或提交答案。

## 与旧规则的关系

本规范新增普通通知不抢页的例外，取代 spec 0029 的固定插队顺序和待确认永远最高的规定。
其余默认会话列表、插队结束恢复原页、机主手动选择、投送和退屏规则继续适用。
优先通知已显示后，通知页成为之后 Agent 插队的返回目标，处理结束不能恢复旧 Agent 页。

## 实现边界

`DisplayPriority` 负责四项顺序归一；`DashboardCore` 是显示仲裁的唯一出口。
待跳转集合仅保存触发通知的 key 与包名，移除精确取消；快照不创建待跳转。
`DisplayPriorityStore` 只保存开启应用的包名和顺序；旧安装缺键默认空集合与默认顺序。
白名单管理页保留增删和应用排序；主屏设置页显示固定四行拖动手柄，提供无障碍上移/下移。
