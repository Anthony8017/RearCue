# Spec 0018：Agent Mirror 扩展——DSH 接入、Remote Approval、Agent Alert、完整历史与稳定性

状态：已与机主 grill 收口（2026-09-30，三轮 Q1–Q12，frontier 空，末轮「都按推荐」），待实现。
术语采用 CONTEXT.md 的 Agent Mirror、Remote Approval、Agent Alert、Session Lock、Waiting-for-Approval、PC 桥、Bridge Link、Prompt Bubble、Mirror Text Size。
红线「不做遥控」由本 spec 反转为「**除批准外只读**」（ADR 0009）；DSH 接入路径见 ADR 0010。
交付节奏：**一批全落、一次实机验收**（机主定夺，不分批）。测试落位经机主确认：四个既有卡点、零新增缝。

## Problem Statement

机主在电脑上并行使用四种 agent：ZCode、Codex、Claude Desktop（已镜像到背屏）与 DeepSeek Harness（DSH，**看不到**）。四个真实痛点：

1. **DSH 会话是盲区**——三种 agent 都能上背屏瞥见，唯独 DSH 干活时背屏一片空白，机主不知道它在干什么。
2. **等确认必须回电脑**——agent 停下等批准时，机主哪怕就在手机旁，也得走回电脑点一下；不点它就一直停着，工作流被打断。
3. **提醒叫不到人**——等待确认/干完/出错目前只有背屏视觉标记（脉冲、光带），人一离开手机旁就错过；锁屏下手机也不会响一声。
4. **翻不到更早、心里没底**——回看只有最近一段输出，昨天/更早它干过什么翻不到；桥偶发不稳、整夜挂机耗电也让机主不放心。

## Solution

从机主视角，五件事：

1. **DSH 上背屏，同等待遇**：DSH 会话像 Codex/Claude 一样进 Agent 页与会话列表（来源标记区分），可 Session Lock、等确认同样插队提示；接入复用现有 PC 桥，电脑上零新增安装。
2. **手机上直接批准**：等确认时在通知栏、主屏 App、背屏三处任一处点「同意/拒绝」，选择题点选作答；背屏点一下先弹两个大按钮再点生效（防误触）；**免解锁、点了即生效**。只读红线反转为「除批准外只读」——发 prompt、按键、自由文字输入永不做。
3. **Agent Alert 叫到人**：等你确认、任务干完、出错三类事发生时，手机通知栏＋震动提示（不响铃），带一句摘要（如「想修改 xx 文件」），不带输出原文；有总开关、震动可关。
4. **完整历史可翻**：当前会话从头到尾都能回看（不限最近窗口）；仍不做跨会话翻页与搜索。
5. **省心省电**：断线自动恢复、隧道自愈、动作请求不悬挂、整夜待机耗电增幅不可感。

## User Stories

1. 作为机主，我希望 DSH 会话也显示在背屏 Agent 页，以便四种 agent 干活时都能瞥见。
2. 作为机主，我希望会话列表合并 ZCode / Codex / Claude / DSH 四来源并带来源标记，以便一眼分清谁是谁。
3. 作为机主，我希望 Session Lock 对 DSH 会话同样有效，以便盯住我最关心的那一个。
4. 作为机主，我希望 DSH 会话进入等待确认时同样插队显示、亮脉冲与确认光带，以便绝不错过。
5. 作为机主，我希望 DSH 向我提问（选择题）也按「等你」语义提示，以便它卡住时我知道该拍板。
6. 作为机主，我希望 DSH 断线时内容停在最后一帧、链路状态点照常提示，以便分清「它停了」和「线断了」。
7. 作为机主，我希望 DSH 会话沿用同一套问答流版式（提问泡、左对齐、三档字号），以便四个来源观感一致。
8. 作为机主，我希望等确认时在通知栏直接点同意/拒绝，以便不用解锁开 App 就能处理。
9. 作为机主，我希望主屏 App 里也能点同意/拒绝，以便我正在看手机时顺手处理。
10. 作为机主，我希望背屏上也能点批准（先弹「同意/拒绝」两个大按钮、再点才生效），以便手机扣着时直接翻过来处理。
11. 作为机主，我希望 agent 的选择题在手机上点选项即可作答，以便拍板类等待不用回电脑。
12. 作为机主，我希望批准免解锁、点了即生效，以便最快恢复它干活（误触风险我自担）。
13. 作为机主，我希望批准成功后等待标记立刻消失、背屏回到它的输出，以便确认处理生效了。
14. 作为机主，我希望批准失败（桥断、来源不支持、超时）时明确告诉我一声，以便不误以为批上了。
15. 作为机主，我希望手机上永远没有自由文字输入框，以便它不会变成遥控器。
16. 作为机主，我希望 agent 等我确认时手机通知栏＋震动叫到我，以便人不在屏幕旁也不错过。
17. 作为机主，我希望任务干完了也提醒我一声，以便不用一直盯着它跑。
18. 作为机主，我希望它出错/崩了也提醒我，以便及时救场。
19. 作为机主，我希望提醒带一句摘要（它想干什么），以便抬手就知道要不要管；但不要带输出原文（锁屏别人看得到）。
20. 作为机主，我希望有提醒总开关、震动可关，以便开会/睡觉时不被打扰。
21. 作为机主，我希望实时新输出不提醒（背屏已是实时），以便不被刷屏。
22. 作为机主，我希望同一件事不重复提醒，以便多会话并行时不轰炸。
23. 作为机主，我希望提醒走系统通知，以便在通知栏/锁屏按系统习惯呈现。
24. 作为机主，我希望回看当前会话的完整历史（从头到尾），以便查它更早干过什么。
25. 作为机主，我希望回看中锁位语义不变（上滑暂停、点 ↓ 恢复、前部挤出不位移），以便翻旧账时不错行。
26. 作为机主，我希望翻长历史顺滑不卡顿，以便实际用得下去。
27. 作为机主，我希望断线自动重连、隧道掉了自动重拉，以便不用我手动救。
28. 作为机主，我希望批准请求失败不悬挂（超时给回执），以便界面不卡在「已发出」。
29. 作为机主，我希望整夜挂机耗电增幅不可感，以便放心长期开着。
30. 作为机主，我希望 DSH 版本不达标时只显示 DSH 来源不可用、其余功能照常，以便不被一个来源拖死。
31. 作为开发者，我想把提醒判定、批准生效判定做成纯函数判例，以便显示语义锁死。
32. 作为开发者，我想用调试旁路注入伪状态跑「等确认→三处批准→提醒→状态推进」验收链，以便不必真开 DSH 也能验。
33. 作为开发者，我想桥单源格式变更不崩桥（解析失败降级只读已知段），以便版本漂移不牵连全链。
34. 作为开发者，我想新来源只动桥适配器与显示映射两处，以便以后再接新 agent 成本可控。

## Implementation Decisions

### 一、DSH 接入（第四来源）

- **复用现有 PC 桥**（ADR 0006）：与 Codex/Claude 同一进程、同一会话事件契约；桥内新增 DSH 适配器，手机侧零新增安装。
- **数据获取＝自写只读 DSH 插件**（ADR 0010）：订阅 DSH 官方会话事件流——会话增删、运行状态、活动、审批请求、用户提问请求——**只订阅、不调用任何写方法**；桥经本机回环接收插件转发的事件。不用 dsh-remote-web-ui 当通道（它是全权遥控通道、非只读，与「除批准外只读」冲突），仅作协议参考。
- **版本门槛**：DSH ≥ 0.2.0-rc.2，实现期实测核对；不达标时 DSH 来源显示为不可用（会话列表不出现），其余功能照常。
- **归一**：进统一事件契约的既有词表（working / waiting / idle）；DSH 的审批请求与用户提问请求都归入 waiting 语义；来源标记沿桥来源命名惯例（第四值），手机侧补来源常量与显示映射两处，仲裁与渲染零来源特例。
- **摘要字段**：事件契约新增可选「当前摘要」（一句话，用于 Agent Alert 与批准上下文），缺失时提醒退化为会话名＋事件类型。

### 二、Remote Approval（远程批准）

- **红线改写**：除批准外只读；批准＝**同意/拒绝**＋**选择题点选**；自由文字输入、发 prompt、按键永不做（不做输入框）。
- **动作请求方向（手机 → 桥）**：新增「会话动作」契约——同意 / 拒绝 / 选中某选项，带会话键与请求标识；桥按来源分发：DSH 经只读插件的应答通道回给官方审批/提问流；Codex/Claude 走各源本地批准通道。
- **来源能力表**：桥对每个来源声明「可批准/只提醒」；手机按能力表决定显不显示批准入口。能拿到等待语义的来源开批准；**来源不齐不挡发布**（机主定夺）——ZCode 直连若无动作通道则只提醒不批准。
- **入口三处、同一动作语义**：通知栏动作按钮（同意/拒绝）、主屏 Agent 区、背屏。背屏**仅「等确认」那一屏**响应：第一下弹出「同意/拒绝」两个大按钮，再点才生效（二次确认防误触，机主确认）；其余屏不响应批准。
- **免解锁**：点了即生效，不走系统解锁验证（机主定夺，误触风险自担）。
- **回执**：成功 → 等待标记消失、会话状态推进；失败（桥断/来源不支持/超时）→ 主屏与提醒各提示一句，不自动重试轰炸。

### 三、Agent Alert（Agent 提醒）

- **判定纯函数**：会话状态变化 → 提醒种类（等你确认 / 干完 / 出错）或不提醒；工作中、实时输出、空闲一律不提醒；同一会话同类提醒去重＋冷却，多会话并行不轰炸。
- **呈现**：系统本地通知＋震动（不响铃）；摘要一句＝会话标识＋事件类型＋当前摘要（如「想修改 xx 文件」），**不带输出原文**（锁屏可见性取舍，机主定夺）。
- **开关**：提醒总开关（默认开）、震动开关（默认开），主屏 Agent 设置区；Agent Mirror 总开关关着时提醒整体不存在。
- **与背屏标记并行**：会话标识行脉冲、Approval Glow 照旧；提醒是手机侧新增，不替代也不改动背屏视觉语言（不响不震原则只约束背屏）。

### 四、完整历史

- 桥对每个镜像会话保留**完整问答历史**（不再只留最近窗口），手机可取全量；实时增量仍走既有事件流。
- 回看交互沿既有滚动策略语义（上滑暂停进回看、点 ↓ 恢复跟随、回看中前部挤出不位移、回看中冻结字号档）；长历史以追加方式进入视口，目标顺滑不掉帧。
- ZCode 直连源：历史以中继快照给到的为限（快照给到哪翻到哪），不为全量历史攻坚私有协议。

### 五、稳定性与省电

- 桥隧道看门狗、重连退避沿既有机制；新增动作请求失败不悬挂（超时回执）。
- 手机侧链路节奏沿既有 Bridge Link 机制微调；目标：整夜待机耗电增幅不可感（实测口径见验收）。
- 免解锁批准与震动提醒均提供开关，随时可关。

## Testing Decisions

- **好测试的口径**：只测外部行为（事件进 → 判决/请求出），不测实现细节；判例沿既有纯函数与协议缝惯例，数值判例锁死版式与参数。
- **测试落位（四个既有卡点，零新增缝，机主 2026-09-30 确认）**：
  1. **桥统一事件契约与手机侧归一**（既有 BridgeEventCodec / BridgeRelayClient 快照判例、桥侧适配器与桥判例惯例）：DSH 适配器翻译判例（事件流 → 统一契约）、状态词表归一、第四来源映射、会话动作请求契约（含超时回执）、完整历史读取契约。
  2. **会话状态归一与仲裁**（既有会话状态逻辑、会话锁定索引、Dashboard 仲裁判例惯例）：提醒判定纯函数（三类触发、非触发不提醒、去重冷却）、DSH 会话进册/清锁/等待插队回归、来源能力表驱动的批准入口判定。
  3. **背屏版式与交互纯函数**（既有版式参数、选择器参数、滚动策略判例惯例）：批准浮层可点区与生效判定、二次确认状态机（第一下弹层/再点生效/点外取消）、长历史回看锁位回归。
  4. **调试旁路注入（既有验收链）**：伪状态跑「等确认 → 三处批准入口 → 提醒 → 状态推进 → 失败回执」全链，不必真开 DSH。
- **回归底线**：全模块既有判例全绿；实机验收一次（含真 DSH 会话冒烟、免解锁误触观察）。

## Out of Scope

- 自由文字输入、发 prompt、按键（永不做）。
- 跨会话翻页与跨会话搜索。
- 更多来源（Cursor、Gemini CLI 等）本期不接（机主明确砍掉）。
- 打码档。
- DSH < 0.2.0-rc.2 的兼容支持。
- 采用 dsh-remote-web-ui 全权遥控通道当接入路径（ADR 0010 判出局）。
- 批准动作的撤销/回滚。
- 响铃、来电式强提醒。
- 批准的二次解锁档（若实机误触明显再立票，不回退只读红线）。
