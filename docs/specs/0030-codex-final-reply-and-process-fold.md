状态：Q1–Q3 经机主「确认」统一收口并实现；测试、构建与装机边界见文末。

## 已明确的目标

Codex 每轮完成后，Agent Mirror 的正式回答内容与 Codex 最终答复一致。
任务期间的进度说明、来源公开的思考记录、工具调用及工具结果归入该轮过程，完成后默认收起，提供过程总结与展开入口。
折叠保留原始记录，不删除内容，不把过程总结混入正式回答，也不将多轮过程合并。
本次沿用 spec 0028 的背屏范围、入场锚点及阅读位置规则；不扩展手机主屏正文页。

## 实施时需要覆盖的边界

- 落盘历史与实时接入使用一致的正式回答/过程分类，重入、补历史和完成事件不得重新把进度说明放回正文。
- 既有桥历史来自已分类的内存记录，不能认为修改解析后旧记录自然被重新分类；修正需明确既有会话重放与兼容边界。
- 优先使用来源明确的消息阶段与真实回合结束事实，不凭文本长短或最后一条 assistant 消息猜测正式回答。
- 无明确最终答复时，不将进度说明冒充正式回答；停止、失败与等待仍按已确认的生命周期规则显示。
- 每轮最终答复完整保留原文内容，过程归组不吞记录、不重复记录；已有历史回看、详情与人工展开规则按机主最终决定执行。
- 本样本应能在末轮完成后只看到机主消息、正式回答及一个收起的过程入口；展开后原过程记录可查。

- 历史落盘与 app-server 共用阶段分类：明确的最终阶段为正式回答，进度与阶段尚未知的增量先归过程。稳定消息标识使完成元数据原地补全正文与类别，不产生第二份回答；旧来源由明确的完成文本补正式答复。
