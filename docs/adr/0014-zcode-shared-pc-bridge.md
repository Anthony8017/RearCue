# 14. ZCode 纳入共享 PC 桥：四源统一走桥，直连退役

日期：2026-10-01
状态：已接受（grilling 定案；实现待办）

## 背景

2026-10-01 grilling 重新审视 Agent Mirror 的接入边界。ADR 0005/0006 原本把 ZCode 作为
「官方远控中继直连、零安装」的第一期，并把它与 PC 桥分成两条通道；机主本轮明确选择
**ZCode 也走 PC 桥**，且不保留 ZCode 直连兜底。

本决策只改变连接方式，不改变用户在手机上看到的 ZCode 镜像能力：会话标题、回复原文、
等待确认、提醒和远程批准均保持现状。Claude Desktop 的 Chat 标签仍不镜像，沿 ADR 0006。

## 决定

| 决策点 | 定案 |
| --- | --- |
| ZCode 通道 | **只走 PC 桥**；ZCode 官方远控中继直连退出产品路径，不保留直连兜底 |
| 统一范围 | ZCode、Codex、Claude Desktop、DeepSeek Harness 四类 Agent Mirror 来源统一走同一个 PC 桥 |
| 使用前提 | 首次配置一次桥，之后由常驻桥自动运行；机主只需关心桥是否正常 |
| 桥不可用 | 显示断链并保留最后一段内容；桥恢复后自动恢复实时镜像 |
| 产品行为 | ZCode 的标题、回复、等待确认、提醒、远程批准行为不变；只改连接方式 |
| 故障边界 | 接受「桥故障时四类来源一起暂时断」的统一单点；不另设 ZCode 独立故障路径 |

## 后果

- **取代 ADR 0005 的 ZCode 直连优先/回退方案**：ZCode 不再占官方远控中继的手机配对槽位，
  也不再要求手机端理解其私有远控协议。
- **取代 ADR 0006 的两条通道设计**：「ZCode 独立不受牵连」和「ZCode 保持零安装」不再成立；
  ADR 0006 中桥生命周期、托盘、隧道自愈等非路由决定继续有效。
- ZCode 从「PC 端零安装」变为与 Codex/Claude/DSH 相同的「PC 桥前置条件」。首次配置成本
  由机主承担一次，之后不把桥的启停暴露成日常操作。
- 一个桥成为四源共同故障点，这是换取统一镜像模型、统一状态和统一恢复体验的明确取舍。
- ZCode 的会话标题仍以 ZCode 会话索引为准；标题、来源、目录名的展示派生不变。
- 远程批准仍是窄写能力：只允许同意/拒绝和选择题点选，不恢复 prompt、按键或自由文字输入。
