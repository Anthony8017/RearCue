# 会话已阅状态拆分空闲状态点

2026-10-03 机主定夺：Agent Mirror 的“空闲”还要回答“完成结果看过没有”，但不能把这件事混成新的工作状态或重复提醒。规则以 Codex 的目标体验为参照——电脑端或手机端点开会话就算已阅；OpenAI 官方文档没有正式定义未读/已阅同步，因此本 ADR 把它固定为 RearCue 的产品契约，而不声称是官方公开保证。

## Decision

- 会话已阅状态适用于 ZCode、Codex、Claude Desktop 与 DeepSeek Harness 四源。完整的新回答产生后进入「空闲·没阅」；在来源软件端或 RearCue 主屏、背屏实际打开正文即「已阅」，同一会话跨端共享。正文正在展示时出现的新回答继续算已阅；锁屏、退出或切走后出现的新回答才重新算没阅。
- 会话列表中：工作中＝蓝点、等待确认＝琥珀黄点、出错＝红点；空闲没阅＝绿点、空闲已阅＝不画点。断链时无论已阅与否都以灰点压过，恢复后回到前述规则。
- 打开未阅正文时，标题行仍显示空闲绿点来表达当前会话状态；已阅事实在返回会话列表时体现为状态点消失。Status Glow 不参与已阅/没阅，空闲已阅仍保持绿色低亮。
- 没阅不新增响铃、震动或语音提醒，也不改变「等待确认置顶 → 其余最近活跃优先」的排序。功能启用前已经存在的空闲会话全部先算已阅，之后才由新回答产生没阅。
- 来源软件无法提供跨端已阅事实时，至少保证打开 RearCue 正文即已阅；界面不得把本地退化误说成跨端同步。
- Codex 电脑端的已阅事实只读自 Electron 自身的 `electron-thread-read-state-v1.unreadByIdentity`：thread id 从未读集合移走即实际打开过正文。读取失败或载荷异常时沿用上一事实，不把坏读误判成已阅；其他来源仍按同一回执接口接入。

## Consequences

- 只修改 ADR 0016 中“空闲恒为绿点”的部分：工作中、等待确认、出错以及断链灰档不变；空闲绿点改由「没阅」触发。ADR 0016 保持历史原貌，以本 ADR 为现行口径。
- 会话状态与会话已阅状态成为两个不同问题：前者回答“现在怎么样”，后者回答“完整结果看过没有”。
- 与通知角标里的「未读数」完全分开；后者仍是 Shade-visible Notification 条数，不是 App 内部或 Agent 会话的未读数。
