# 11. 托盘与桥互盯生命周期：不合并两进程，先补图标后关桥＝保手机优先

日期：2026-09-30
状态：已接受（grilling 三轮定案；spec 0019）

## 背景

托盘图标是 PC 桥唯一的人机界面，机主靠它判断桥在不在。既有机制只保证单向
「桥停 → 图标消失」（托盘轮询父进程与桥端口）。2026-09-30 实测暴露反向的洞：
托盘自行退出（code=0）后，桥**无图标跑了约 53 分钟**——机主看「没图标」以为桥停了，
实际后台还在跑、还在占端口；同日桥被外部信号终止 3 次。图标从此不可信。

候选与取舍：

| 候选 | 取舍 |
| --- | --- |
| **两进程互盯**（托盘盯桥已有；桥新增监护托盘：消失即补拉 3 次×10 秒，补不回则桥先广播「清除桥地址」再优雅自关；开机自启计划任务重来 3 次×30 秒，耗尽即彻底停） | 双向不变量「图标在 ⇔ 桥在」成立；彻底停后手机靠临终通知/超时判停显示「未配置或已停用」，不再无限转圈；**采纳** |
| 合并托盘与桥为单进程 | WinForms 托盘要 STA 消息循环，进程内一处崩溃（UI 或桥）连坐整棵「图标＋桥」；托盘引 .NET/UI 依赖破坏桥的零 npm 依赖；断屏风险（桥崩=屏断）；**否决** |
| 只修托盘自退（加留痕/告警），桥仍不动作 | 留下「看不见的后台进程」继续占端口，机主无从恢复信任；**否决** |

## 决定

1. **不合并托盘与桥**：桥保持零 npm 依赖的纯 Node 进程，托盘保持独立
   PowerShell+WinForms 进程；两者互盯、各自可单独死。
2. **先补图标后关桥＝保手机优先**：托盘消失，桥先补拉图标（3 次×10 秒，补回即清零
   失败计数）；只有连续补不回才自关。取舍的是：监护误判时宁可短断屏，也不留一个
   「图标没了但桥还在跑」的假象——手机侧优先获得真实状态（临终通知复用既有
   「清除桥地址」广播语义，发不出不重试，靠手机超时判停兜底）。
3. **重来引擎＝开机自启计划任务**：失败重启 3 次×间隔 30 秒（对齐产品节奏）；耗尽即
   **彻底停**，无人再拉起——恢复＝重新登录（登录自启）或电脑上手动一条命令，
   不做无限重启折腾电脑。
4. **退出留痕双侧落盘**：桥（信号类型＋父进程链＋PID＋时刻＋原因）与托盘
   （桥没了／探不通／被接管／手动退出四类）各自留痕；Windows 硬杀（taskkill /F、
   Stop-Process -Force）受害者收不到信号，由目击者（托盘）留痕兜底。
5. 手机侧 Bridge Link 四态语义不变，新增两条边沿：重连失败累计约 2–3 分钟降级
   「未配置或已停用」（超时判停，底层继续重连、恢复自动翻回已连接）；收到临终通知
   立即降级。

## 后果

- 托盘与桥的契约保持「状态文件＋事件文件＋命令行参数」三条既有缝，零新增协议；
  手机端无需任何改动即可接住临终通知。
- 彻底停是终态：无人值守下系统不会再自拉起，需要机主在场恢复（明确路径，取舍自认）。
- 计划任务失败重启的秒级间隔受 Task Scheduler 粒度限制，注册参数以实测为准
  （注册脚本与实测必须一致，spec 0019-4）。
- 桥新增托盘监护职责后，桥进程的退出路径全部收口 `shutdown()` 单一入口，
  后续新增退出原因只加 reason，不再散落 `process.exit`。
