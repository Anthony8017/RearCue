# 飞书通知发送完整 Bridge URL

状态：已接受（2026-10-04 grilling；票 #303）

桥地址自动轮换后，机主需要一条能直接复制到手机的连接链接。我们决定：第一次拿到可用地址及后续每次地址真正变化时，
飞书私聊正文只发送完整 Bridge URL（含访问 fragment）；电脑安装了飞书就先打开飞书再发送，通知只做尽力而为，
不排队、不补发。曾考虑只发脱敏 base URL以降低泄露面，但它不能直接完成手机连接，且机主明确选择复制便利优先。

代价是飞书聊天记录会保存可主动操作桥的连接能力，转发或账号泄露会扩大风险；因此 bridge.log 与去重状态仍只保存脱敏地址，
同一地址不重复发送，发送失败也不循环重试，以限制暴露次数与打扰。
