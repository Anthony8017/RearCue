# 模型按钮显示当前模型，手选失败则不发送

2026-10-11，机主经 grill-with-docs 确认。已实现。取代 ADR 0024 中「桌面持有会话时拒绝手选模型并提示改回自动」的产品口径；队列不能携带模型的事实不变。

## Context

对话页和新建窗口都把未手选显示为「自动选择可用模型」。这和会话列表的「自动」档不是一回事。桌面空闲仍持有会话时，手机只能把文字交给桌面，交不了模型；因此旧口径在手选时直接拒绝，并要求改回自动。机主要求按钮直接显示模型名，且电脑开着这条对话时这句也要换成手选模型。

## Decision

未手选时按钮显示当前模型；新建窗口显示默认模型。Codex 桥从会话记录同步真实当前模型，优先于手机本地发送缓存，因此冷启动、清包或换机后仍能显示该会话的模型。只有来源确实未提供模型时才显示「模型未知」。显示不是手选，发送仍跟着这条对话走。名单不设「自动选择可用模型」。点当前模型（未知时点「模型未知」）取消手选；勾跟着按钮。手选只对当前这条有效，离开页面再回来还在。

当前模型已不在名单里时，按钮仍显示它；没手选就照旧发，只有真发不出去才请另选。名单末尾保留该名字，注明只能改回、不能新选。手选模型变得不能用时不发送，草稿和手选留着，请另选或改回，不偷偷换掉。

电脑开着这条对话时，手选仍要用于这句，电脑窗口可以被这轮打断；发送前不再询问。以现有交接做不到时不发送，输入框旁说明没换成所以没发，不提供「改回并发送」。电脑正在回答时本来就不能发。一旦用该模型发出去，它变为当前模型，下一句未再改则交给电脑，不再为换模型打断。没发出去或结果未知时手选留着，不自动重发。

## Considered Options

- 电脑开着就不许换模型，提示改回自动。已拒绝：机主要这句就用新模型。
- 做不到时偷偷用旧模型发出去。已拒绝：不能假装已经换了。
- 失败时提供「改回并发送」。已拒绝：避免误触把没换成的消息发出去。

## Consequences

桌面持有会话时，手选模型不能经队列更换，手机会收到「没换成，所以没发」且不投递。不得再把「自动选择可用模型」当作未手选的文案或恢复路径。成功换模型可能打断电脑上的该对话窗口；失败必须保持草稿与手选，并与发送状态未知的既有规则并存。
