# 9. 「不做遥控」红线反转：Remote Approval——除批准外只读

日期：2026-09-30
状态：批准部分仍有效；「发 prompt 永不做」由 ADR 0017 部分取代

## 背景

Agent Mirror 自 spec 0010 起立有红线：手机端只读，**绝不发送 prompt/按键/批准**；
Waiting-for-Approval 只能回电脑处理。2026-09-30 grilling 里，机主面对「等确认必须回电脑、
人不在电脑旁就卡住」的真实痛点，在两案（维持只读 / 放开批准）中拍板**放开批准**：

| 决策点 | 定案 | 取舍 |
| --- | --- | --- |
| 红线 | 反转为「**除批准外只读**」 | 换来不必回电脑；承担误触与安全风险 |
| 应答范围 | 同意/拒绝 ＋ 选择题点选 | 自由文字输入＝变相 prompt，永不做（不做输入框） |
| 解锁门槛 | **免解锁**，点了即生效 | 机主自担误触风险（Q4「不要」） |
| 背屏护栏 | 二次确认：第一下弹「同意/拒绝」两大按钮、再点生效 | 免解锁下唯一护栏，不得省 |
| 入口 | 通知栏按钮 / 主屏 App / 背屏三处，同一动作语义 | 背屏仅「等确认」那一屏响应 |

## 决定

批准（同意/拒绝、选择题点选）是手机端**唯一**可写动作；发 prompt、按键、自由文字输入
永不做。三入口同一动作语义；来源按能力表开批准入口（拿不到等待语义的来源只提醒不批准），
来源不齐不挡发布。口径以 CONTEXT.md「Remote Approval」为准。

## 后果

- spec 0010/0017 的「永不批准」判例由本 ADR 反转；**prompt 与按键部分不变**。
- 手机→电脑新增一条窄动作通道（会话动作契约），桥协议第一次出现请求方向；
  动作仅限批准类，凭据语义不变（Bridge URL 仍是接入地址、不是控制凭据）。
- 安全面从「纯只读」变为「只读＋一条窄动作通道」：动作需带会话键与请求标识、
  超时回执不悬挂；暴露面沿 ADR 0005/0006 的隧道既有设计，不另开新面。
- 若实机验收误触明显，立票加「批准二次解锁档」，不回退只读红线。
