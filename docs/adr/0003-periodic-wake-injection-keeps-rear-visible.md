# 用周期轮询换可见：唤醒保活推翻 spec 0001 story 20 的非轮询原则

spec 0001 story 20 只认可非轮询的保活手段；spec 0003 的设备事实证明在 HyperOS 3 上没有可用的
非轮询面（覆盖窗口通道 no-go、锁屏断电后 Dashboard 1.3–1.4s 被收走，KEEP_SCREEN_ON 类手段无处
可依），而周期注入**定向背屏**唤醒键（Wake Keep-alive，CONTEXT.md）是本机唯一守住锁屏可见性的
手段（E12：keep 腿 62s 全程 ON vs 对照腿 +5s 离开 ON；E13：跨锁 60s Dashboard 全程在屏，对照
1.3–1.4s 被收走）。决定采纳 Wake Keep-alive——**用周期轮询的耗电/发热代价换锁屏可见性**，
story 20 的非轮询原则就此废止。

## Considered Options

- **周期注入定向背屏唤醒键（选定）**：可见性实测成立（E12/E13，见 findings）；代价 = 耗电/发热，
  间隔做成可调参数，实测代价数据随票 #21 记录（user story 10/18）。
- **坚持非轮询手段（否决）**：等于放弃锁屏可见性，主诉求（锁屏闲置来通知、背屏一直看得到）落空。
- **不做保活、仅解锁态收口（否决的兜底）**：spec 0003 no-go 时的交付形态；探针全过后不再需要，
  但保留为重开条件 1 的退路（findings「探针收口与 go/no-go」）。

## Consequences

- 注入循环的生命周期绑定 Icon Set（有指示才跑、无指示即停），强度（注入间隔）可调；
  默认值以票 #21 的耗电/发热实测定，不在本 ADR 预设。
- 设计评审里「不许轮询」的检查项移除，改查两条：循环是否跟随指示启停、代价数据是否如实记录。
- 重开条件：①非轮询手段在背屏显示组实测常亮成立（换手段、撤销本取舍）；②唤醒注入被系统拒或
  失效（E12 失败条件形态复现，`ex.ps1 -Task wake-keepalive` 一键复跑作证）→ 重新走探针判定。
