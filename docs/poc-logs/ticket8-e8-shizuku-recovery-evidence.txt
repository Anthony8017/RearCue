# 票 #8 原始证据：Shizuku 恢复后自动重投（2026-09-22 11:55-12:15）
# 设备 94250f9e（小米 17 Pro / HyperOS 3.0.319.0）；命令与回显按序记录，logcat 均为原文摘录
#
# 结论：票 #6 记的「根因 = server 以裸 shell uid 拉起」是误判。真因是本应用自己的两处声明写错，
# 与 server 由谁拉起无关：
#   ① app/src/main/AndroidManifest.xml 的 ShizukuProvider 用 moe.shizuku.manager.permission.API_V23
#      （dangerous，shell 不持有）保护 → server（uid 2000）回调被拒 → pingBinder() 恒 false。
#      官方文档要求 android:permission="android.permission.INTERACT_ACROSS_USERS_FULL"（shell 持有）。
#   ② rear/src/main/kotlin/.../RearShellService.kt 写成了 Android Service；Shizuku 的 UserService
#      必须是 IBinder（IRearShell.Stub），否则启动即 ClassCastException + System.exit(1)。
# 两处修好后：server=true granted=true userService=true，兜底通道真的跑起来了（见 [E]）。
